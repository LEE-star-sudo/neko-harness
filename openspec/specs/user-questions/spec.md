# user-questions Specification

## Purpose
为主 agent 提供可持久恢复的结构化用户问答，使用户在 Web、TUI 或手机客户端选择选项、补充文字或明确跳过后，模型从同一次工具调用继续。问题、回答与取消共享统一真相，不依赖单个前端的连接或内存等待。

## Requirements

### Requirement: 主 agent 结构化提问
系统 SHALL 向主 agent 提供 `ask_user` 工具，每次调用提出一道非空问题，允许零个或多个带稳定 ID、标签、可选说明及可选 `recommended` 标记的选项，并可声明 `multiple` 使其为多选（默认单选）。用户 SHALL 可选择选项、填写文字（可与选项同时提交，作为补充说明；无选项时即自定义答案），也可明确跳过。选项 ID 与标签（trim 后）在同一问题内 MUST 唯一；`multiple` 至少需要 2 个选项，单选问题至多一个 `recommended`，无选项时 `multiple`/`recommended` 非法。`recommended` 仅作提示，MUST NOT 预选、预填或自动提交。首版 MUST NOT 提供任意表单、单次调用内的多题问卷或子 agent 直接提问。

#### Scenario: 单选、多选与自定义答案
- **WHEN** 模型提出带选项的问题，用户选择一个选项、选择多个选项（多选问题）、仅输入文字，或选择选项并附加文字
- **THEN** 结果分别保存选中的选项 ID（按问题选项顺序）与用户文字，模型收到用户实际提交的内容，选项 ID 与文字不混为一谈

#### Scenario: 推荐标记仅作提示
- **WHEN** 问题中某选项带有 `recommended`
- **THEN** 三端显示“推荐”并以其为焦点起点，但没有任何选项被预选，用户未显式提交前问题保持未决

#### Scenario: 自由问题和非法参数
- **WHEN** 模型不提供选项，或提供重复选项 ID/标签、空白问题、空白标签、超限内容，或对单选问题设置多个 `recommended`、对不足 2 个选项的问题设置 `multiple`
- **THEN** 无选项的有效问题可正常回答；非法输入明确失败且不产生未决问题

#### Scenario: 子 agent 工具集
- **WHEN** 子 agent 新建、接续或恢复
- **THEN** 其工具集不含 `ask_user`，需要用户决策时只能向主 agent 报告

### Requirement: 回答对模型的呈现
`ask_user` 的工具结果 SHALL 明确区分 `answered`、`skipped` 与 `cancelled`，供模型和历史展示使用。已回答的结果 SHALL 同时包含每个选中选项的标签与 ID，以及用户文字，并标明文字来自用户；跳过的结果 SHALL 说明用户未提供答案、这不代表同意、拒绝或偏好，模型应基于自身判断继续并说明假设，且不在情况未变时重复同一问题。历史展示 MUST 来自持久的结构化 details 而非解析结果文案。

#### Scenario: 模型读到有语义的答案
- **WHEN** 用户在多选问题中选了两个选项并附加一句说明
- **THEN** 模型收到两个选项的标签与 ID 及该说明，而不是仅有不透明的 ID

#### Scenario: 跳过不被当作同意
- **WHEN** 用户跳过问题
- **THEN** 结果说明未提供答案且不构成任何选择，模型不得据此假定用户同意；原运行未被用户停止

### Requirement: 等待与专用回答通路
有效问题 SHALL 在展示前持久保存，具有会话及调用绑定的稳定身份和版本；回答前该工具 SHALL 保持未完成。问题 SHALL 区分 `pending`、`answered`、`skipped`、`cancelled`。回答和跳过 MUST 使用专用控制接口，返回该工具结果而非新用户消息，不进入普通输入历史或排队，也不刷新项目资源快照。

#### Scenario: 无前端连接
- **WHEN** 问题建立后没有已连接前端
- **THEN** 继续等待，不自动选择、不超时伪造答案；后续 attach 可查看同一问题

#### Scenario: 回答后继续
- **WHEN** 用户通过任一前端提交有效答案
- **THEN** 该工具返回答案，原运行按正常工具轮继续，不创建第二条用户输入或第二份 agent run

#### Scenario: 普通聊天不是回答
- **WHEN** 问题等待期间用户发送普通聊天或队列中已有输入，或把排队项改为引导
- **THEN** 输入沿现有排队/引导语义处理，不被当作该问题答案，不自动结束提问；排队与引导项都要等该问题结算（或运行停止）后才进入上下文

#### Scenario: 明确跳过
- **WHEN** 用户点击跳过问题
- **THEN** 问题结算为 `skipped`，模型收到“用户跳过、未提供答案”，不得伪造用户选择；原运行未被用户停止

#### Scenario: 同轮多个问题
- **WHEN** 模型在同一轮连续调用多个 `ask_user`
- **THEN** 它们按序逐个呈现，后一个在前一个结算后才出现；同轮排在后面的其他工具调用在对应问题结算后才启动

### Requirement: 问答重启恢复与幂等
同一次调用在等待期、回答持久保存后或工具结果提交前中断，恢复 SHALL 复用同一问题及已有决定，不重复提问、不丢失答案。同一调用若以不同题目或选项尝试复用身份 MUST 明确拒绝。会话分叉 MUST NOT 继承可操作的旧未决问题或消费父会话的答案；历史工具结果保持可读。

#### Scenario: 等待期重启
- **WHEN** gateway 在用户回答前退出并重开同一存储
- **THEN** 同一问题仍可回答，身份、版本、正文、选项不变，原调用继续等待

#### Scenario: 回答后回执丢失
- **WHEN** 答案已持久保存但客户端未收到回执，或工具结果提交前进程退出
- **THEN** 重连查询或重试得到原结算状态，恢复调用使用原答案，不创建新问题或重复模型推进

#### Scenario: 父会话与分叉
- **WHEN** 用户在包含问题历史的会话中创建分叉
- **THEN** 分叉不显示父会话的可操作未决问题，无法用父问题身份向分叉提交答案；已有历史答案不被改写

### Requirement: 多端结算与任务取消
回答和跳过 SHALL 校验所属会话、问题身份及版本，并在持久事务内仅接受第一次有效结算；之后的重复或冲突请求返回原终态，不覆盖答案。停止运行或归档会话 SHALL 使相关未决问题取消，迟到回答不得重启任务。单纯断线或关闭客户端 MUST NOT 取消问题。

#### Scenario: 双端竞争
- **WHEN** Web 提交选项 A 与手机提交文字答案或跳过同一问题并发到达
- **THEN** 只有一个结算生效，各端得到相同终态及实际获胜答案，不以各自本地选择显示成功

#### Scenario: 取消与回答竞争
- **WHEN** 用户停止运行与另一端回答并发发生
- **THEN** 按持久提交顺序处理；取消先发生时拒绝回答，回答先保存时保留事实但仍服从任务停止，不启动新的运行

#### Scenario: 错误身份与无效答案
- **WHEN** 请求使用其他会话的问题、错误版本、不存在或重复的选项、单选问题提交多个选项、无选项问题提交选项、既无选项也无非空白文字，或超限内容
- **THEN** 明确拒绝，不结算问题、不泄露其他会话内容

### Requirement: 三端交互与错误可见
Web、TUI、Mobile SHALL 提供可发现的待回答入口、完整问题与选项、单选/多选、始终可见的文字输入和与关闭分离的明确跳过。问题与选项 MUST 按纯文本呈现（保留换行，不解析 Markdown/HTML、不生成链接或加载图片），界面标注为“助手提问”且与 Bash 审批视觉区分。选择只改变草稿，用户 MUST 显式提交（选项或非空白文字至少其一）；不做点选即提交。关闭问题界面 MUST NOT 等于跳过或停止；新问题不清除聊天草稿。提交期间防止重复点击，错误明确显示且保留答案草稿；离线时禁用控制，不在重连后自动发送答案。旧网关缺少能力时隐藏入口。

#### Scenario: 显式提交与跳过分离
- **WHEN** 用户在手机或 Web 上点选一个选项后未点击提交，或误触关闭/返回
- **THEN** 问题仍为未决、选择保留为草稿；只有“提交回答”会保存答案，只有“跳过”会结算为跳过，二者与关闭控件互不混用

#### Scenario: 自动展开不抢焦点
- **WHEN** 新问题出现时用户正在聊天输入框中输入，或已有其他面板/审批占据焦点
- **THEN** 仅显示带“等待回答”的提示条，不改变焦点和草稿；用户关闭自动展开的面板后，同一问题不再自动展开

#### Scenario: 等待期间的聊天输入提示
- **WHEN** 存在未决问题时用户在聊天输入区准备发送消息
- **THEN** 输入区提示助手正在等待回答，说明消息会排队到回答之后并提供打开问题的入口；发送的消息仍作为普通排队输入，不被当作答案

#### Scenario: TUI 关闭面板不停止运行
- **WHEN** TUI 问题面板处于焦点时用户按 Esc
- **THEN** 仅关闭面板并保留答案草稿，同一次按键不触发停止运行；面板外的 Esc/Ctrl+C 仍按既有行为停止运行

#### Scenario: 问答与聊天独立
- **WHEN** 用户已有聊天草稿并打开问题、编辑答案后关闭界面
- **THEN** 聊天草稿不变，问题仍为未决，再打开同一问题可继续编辑；答案草稿不跨会话或问题复用

#### Scenario: 其他端已结算
- **WHEN** 问题界面打开时另一端已回答或任务停止
- **THEN** 界面更新为实际终态，移除或禁用回答控件，不覆盖已保存决定

#### Scenario: 小屏、键盘与审批并存
- **WHEN** 问题、Bash 审批及排队输入同时存在，用户使用窄终端或手机软键盘
- **THEN** 各交互有明确独立目标，回答不会批准命令或引导输入，完整内容可滚动查看，停止与返回仍可操作

#### Scenario: 等待状态
- **WHEN** 主 agent 正在等待用户回答
- **THEN** 三端可区分“等待用户回答”和模型正在生成，运行仍可停止，已结算答案在对应工具历史中可查看

#### Scenario: 历史中不出现第二个编辑入口
- **WHEN** 用户查看 transcript 中的 `ask_user` 工具行
- **THEN** 工具行显示等待/已回答/已跳过/已取消状态与问题、最终答案摘要，并可定位到问题面板；回答控件只存在于问题面板

### Requirement: 等待回答的跨会话可发现性
会话列表（Web 侧栏、TUI 会话选择器、移动会话列表）SHALL 在目录条目带有“等待回答”标记时以“等待回答”取代“运行中”的呈现，使用户在其他会话中也能发现阻塞；目录标记的契约见 session-gateway。Web 标签页隐藏且当前会话有未决问题时 SHALL 以标题前缀提示并在结算或可见后还原。首版 MUST NOT 提供推送、声音或浏览器通知权限请求。

#### Scenario: 其他会话阻塞可见
- **WHEN** 用户停留在会话 B，会话 A 的主 agent 提出问题
- **THEN** 会话列表中 A 显示“等待回答”而不是“运行中”，用户切换到 A 可直接看到并回答该问题；回答后 A 恢复运行中并随后恢复空闲

#### Scenario: 旧网关与旧客户端
- **WHEN** 新客户端连接不含该标记的网关，或旧客户端连接含该标记的网关
- **THEN** 前者按原有状态显示、不报告不兼容，后者忽略未知可选字段并继续按原有状态显示

### Requirement: 问答资源上限
问题 SHALL 最长 2,000、选项 ID 最长 64、标签最长 200、说明最长 500、自由答案最长 4,000 个 UTF-16 码元，每题最多 12 个选项，回答最多选中 12 个选项（且不超过该问题的选项数）。问题参数及回答参数各自 JSON 的 UTF-8 编码 MUST 不超过 16,384 字节。每个会话最多 8 个未决问题，超限 MUST 明确拒绝新调用，不丢弃现有问题或静默截断内容。

#### Scenario: 多字节和数量边界
- **WHEN** 参数达到规定长度/字节上限，或试图建立第 9 个未决问题
- **THEN** 同时满足各项上限的参数可用，任一超限明确失败；已有问题和答案保持不变

# web-ui Specification

## Purpose

浏览器前端：经 WebSocket 连接会话网关，提供与终端对等的对话、插话与会话管理能力。

## Requirements

### Requirement: 浏览器对话

系统 SHALL 提供 Web 界面，用户可在浏览器中提交输入、查看流式回答与工具调用详情，功能与终端前端对等。

#### Scenario: 打开即用

- **WHEN** 用户在浏览器打开 Web UI 并选择会话
- **THEN** 显示该会话的完整历史，后续事件实时到达

### Requirement: 断线重连

系统 SHALL 在 WebSocket 断开后自动重连；重连后从当前视图状态恢复，不重放历史事件。重连 SHALL 保留当前工作区并优先恢复原会话；原会话已归档时仅回退到同工作区最近使用会话，无可用会话则显示该工作区空态。

#### Scenario: 网络抖动恢复

- **WHEN** WebSocket 断开 10 秒后恢复
- **THEN** 界面自动重连并展示会话最新状态，期间到达的回答完整可见，工作区不变

#### Scenario: 原会话不再可用

- **WHEN** 断线期间原会话被另一前端归档
- **THEN** 重连后选择同工作区最近使用会话或显示空态，不连接其他工作区会话

### Requirement: 静态托管

Web UI SHALL 构建为静态资源，由网关进程托管，无需独立前端服务器。

#### Scenario: 随网关启动

- **WHEN** 网关进程启动
- **THEN** 浏览器访问网关 HTTP 地址即可加载 Web UI

### Requirement: 二次元主题系统

系统 SHALL 使用全站统一的蓝粉白 design tokens：导航（侧栏、顶栏、抽屉）、弹层（菜单、目录选择面板、对话框）、聊天内容、输入卡片（含模型入口与遥测控件）与设置页共用同一樱花粉/天依蓝/白 token 体系，滚动条、表单、焦点环和按钮全站一致。正文与控件字号 SHALL 来自统一定义的紧凑字号阶梯；Markdown 行内代码 SHALL 采用中性浅底样式而非主题色药丸；模型输出的 Markdown 渲染前 MUST 经过消毒。

#### Scenario: 默认浅色主题

- **WHEN** 用户打开 Web UI
- **THEN** 侧栏、顶栏、弹层、聊天区、输入卡片与设置页均呈统一的蓝粉白浅色主题，无中性灰导航区域，正文文本相对背景对比度达到 WCAG AA

#### Scenario: 主题色应用一致

- **WHEN** 界面渲染按钮、链接、状态徽章、聊天气泡、侧栏选中态、滚动条与各级弹层
- **THEN** 颜色、圆角、焦点环与阴影均来自同一套 design tokens，不存在第二套区域主题

#### Scenario: 字号与密度阶梯

- **WHEN** 渲染正文、辅助文字、标题与控件
- **THEN** 字号与间距取自统一定义的紧凑阶梯，聊天区正文基准为 14px 档，无散落的一次性硬编码字号

#### Scenario: 行内代码降噪

- **WHEN** 模型回答包含大量行内代码标识符
- **THEN** 行内代码以中性浅底加等宽字体呈现，不使用高饱和主题色药丸，代码块语法高亮不受影响

#### Scenario: 模型输出消毒

- **WHEN** 模型回答中包含 HTML 标签或脚本内容
- **THEN** 界面渲染为无害文本或经消毒的标记，不执行任何脚本

### Requirement: 工作区会话导航

Web SHALL 以工作区切换器和当前工作区会话列表组织导航，显示可辨识的目录名称和完整路径。首次打开或刷新 SHALL 以 Web 启动时指定的目录或启动目录为初始工作区；进入工作区 SHALL 恢复其最近使用的非归档会话，无会话则展示新建入口。Web MUST 保留访问网关其他工作区的入口。

#### Scenario: 启动目录与共享网关

- **WHEN** Web 从 B 启动或指定 B，复用启动于 A 的网关
- **THEN** 浏览器初始进入 B；会话列表仅展示 B 的非归档会话，用户可通过工作区切换器进入 A

#### Scenario: 切换与同名目录

- **WHEN** 用户在两个同名但路径不同的工作区之间切换
- **THEN** 切换器通过父路径区分它们，可查看完整路径，并分别恢复各自最近使用会话

#### Scenario: 会话排序与搜索

- **WHEN** 当前工作区有多个会话且用户输入搜索词
- **THEN** 列表按最近消息时间降序排列，无消息时使用创建时间，同时间按会话 ID 稳定倒序；搜索匹配当前工作区的标题、首问摘要与 ID，无匹配时明确提示

### Requirement: 工作区内会话操作

Web 新建会话 SHALL 显式绑定当前工作区。归档当前会话后 SHALL 进入同工作区最近使用会话，无会话则保留工作区空态。会话切换与新建期间 MUST 防止重复提交、过期异步结果覆盖新选择或向旧会话误发输入。

#### Scenario: 创建与工具目录

- **WHEN** 用户在 B 中新建会话，而网关启动目录为 A
- **THEN** 新会话保存 B，工具默认在 B 执行，TUI 与 Web 看到相同归属

#### Scenario: 归档当前或其他会话

- **WHEN** 用户确认归档当前会话或其他会话
- **THEN** 当前会话归档后只在同工作区内回退，其他会话归档不改变当前选择；最后一个会话归档后保留工作区且不自动创建会话

#### Scenario: 快速操作与失败

- **WHEN** 用户快速切换工作区或重复点击新建，或服务请求失败
- **THEN** 操作被有序处理，界面选择与可提交输入的实际会话一致，失败有可重试反馈且不会静默切换工作区

### Requirement: 通过宿主目录面板添加工作区

Web SHALL 提供内置目录选择面板，选择 Harness 宿主上的目录。面板 SHALL 提供路径导航、上级目录、完整路径输入、名称过滤、隐藏目录开关、取消与确认。面包屑与路径拼接 MUST 按宿主平台处理分隔符与盘符，不得把 Windows 盘符路径拼接为带前导斜杠的非法形态。Windows 宿主的根层 SHALL 列出可用盘符以支持跨盘选择。只有用户确认且服务端验证成功后才添加并进入工作区；服务端 MUST 归一化带前导斜杠的盘符路径输入。

#### Scenario: 默认位置与确认

- **WHEN** 用户打开添加工作区面板并确认一个目录
- **THEN** 面板默认定位当前工作区或首次使用的 Web 启动目录，固定显示待选目录与确认操作；成功后进入对应工作区，有会话则恢复，无会话则展示新建入口

#### Scenario: 取消与重复添加

- **WHEN** 用户取消选择或选择已存在的真实目录
- **THEN** 取消不新增记录、不改变当前会话；重复选择直接进入已有工作区

#### Scenario: 加载错误与过期结果

- **WHEN** 浏览失败、请求缓慢或关闭面板后旧请求返回
- **THEN** 面板呈现加载或错误反馈并允许取消、重试或输入其他路径；旧响应不重开面板或覆盖新的目录选择

#### Scenario: Windows 盘符路径导航

- **WHEN** 宿主为 Windows，用户经面包屑或路径输入导航 `D:\code` 形式的盘符路径
- **THEN** 面包屑按盘符与双分隔符正确切分与拼回；服务端对 `/D:\code` 这类带前导斜杠的输入归一化后照常浏览，不报路径不可用

#### Scenario: Windows 盘符枚举

- **WHEN** 宿主为 Windows，用户导航到根层（`/`）
- **THEN** 面板列出可用盘符（如 `C:`、`D:`），选择盘符后进入其根目录继续浏览，可跨盘选择工作区

### Requirement: 响应式导航与可访问操作

侧栏 SHALL 采用紧凑行布局、轻量图标与明确选中状态，新建入口持续可见，会话次要操作通过菜单展示。鼠标、键盘和触屏 MUST 均可访问操作；归档 SHALL 使用可取消的明确确认。桌面侧栏 SHALL 可折叠，移动端 SHALL 默认收起并通过抽屉打开。页面 SHALL 提供主内容 landmark 与跳转主内容的 skip-link；移动断点与消息列宽各档位 MUST 在脚本与样式间单一来源，会话悬浮提示 SHALL 与触发元素建立可访问关联。

#### Scenario: 菜单与归档确认

- **WHEN** 用户悬停、键盘聚焦或在触屏访问会话行
- **THEN** 可访问操作菜单，菜单不被列表滚动区域裁切；归档确认不依赖限时二次点击，取消保留会话

#### Scenario: 焦点与抽屉

- **WHEN** 用户用键盘打开和关闭菜单、目录面板或移动端抽屉
- **THEN** 焦点进入对应界面，模态界面约束焦点，Escape 可关闭并将焦点返回触发控件，隐藏侧栏不保留可 Tab 访问的控件

#### Scenario: 键盘直达主内容

- **WHEN** 用户使用键盘首次 Tab 进入聊天页
- **THEN** 出现跳转主内容的 skip-link，激活后焦点落入主内容 landmark；会话悬浮提示可通过 aria 关联被辅助技术朗读

#### Scenario: 小屏幕与长目录

- **WHEN** 在 1440、1024、768 和 375 像素宽度下使用长目录名和长会话列表
- **THEN** 导航、滚动与操作按钮不重叠，路径可查看完整内容，抽屉可关闭且不会遮住无法访问的操作

#### Scenario: 宽屏导航

- **WHEN** 在 1920 或 2560 像素宽度下使用长目录名和长会话列表
- **THEN** 侧栏与顶栏不横向溢出，工作区切换面板与抽屉可正常操作，聊天区列宽按分档抬升

### Requirement: 会话标题与相对时间展示

Web 侧栏 SHALL 为每个会话展示统一名称、距最近消息的相对时间及必要的运行状态；标题优先使用生成结果，其次首问摘要，空会话使用新会话占位。顶栏与归档确认 SHALL 使用相同名称，MUST NOT 展示内部会话 ID（包括提示和辅助技术标签），可通过完整时间辅助区分同名会话。长标题 MUST 不遮挡时间和操作入口。

#### Scenario: 标题异步到达

- **WHEN** 当前或后台会话的标题生成完成
- **THEN** 侧栏及相关会话上下文更新名称，不切换当前会话、不影响输入草稿、不因命名改变排序

#### Scenario: 时间持续更新

- **WHEN** 页面保持打开且最近消息逐渐变旧
- **THEN** 相对时间自动更新，用户可通过鼠标或键盘查看准确时间；时钟偏差不产生负数时长

#### Scenario: 长标题与小屏幕

- **WHEN** 在桌面或移动端展示长标题和长会话列表
- **THEN** 标题适当截断但可查看完整内容，时间与菜单入口可访问，保留导航中性色和聊天区原有主题

### Requirement: 凭据设置页

Web 设置页 SHALL 以美观紧凑的多 provider 列表组织凭据配置，风格与全站统一的蓝粉白 design tokens 一致。每个 provider 条目 SHALL 提供生效来源（含 keyless 等受限来源）、环境变量配置状态、密码输入、保存、移除保存值和对应的密钥申请链接。页面 SHALL 保留返回入口和简短连接状态，不将 serverId、socket 路径等技术详情作为主要内容。已有 Key MUST NOT 回填，保存或离开页面后清除敏感输入。

#### Scenario: 保存和回退

- **WHEN** 用户在已有环境变量的情况下保存 Key，再移除保存值
- **THEN** 来源由环境变量变为保存值再回到环境变量，环境变量状态始终显示已配置；成功后密码框清空

#### Scenario: 多 provider 展示

- **WHEN** 用户打开设置页且 Tavily 未配置任何 Key
- **THEN** DeepSeek 与 Tavily 条目以一致布局并列展示，Tavily 生效来源显示为 keyless 受限而非"未配置"

#### Scenario: 未配置与操作反馈

- **WHEN** 无 Key 时打开聊天或设置，或者保存期间请求失败
- **THEN** 用户可进入设置，发送前有配置引导；保存期间防止重复提交，失败显示可重试反馈而不宣称已保存或已验证

#### Scenario: 响应式与键盘操作

- **WHEN** 在 1440、1024、768 或 375 像素宽度下使用设置页
- **THEN** 各 provider 条目、输入和按钮无横向溢出，所有操作有可访问名称、可见焦点和完整键盘访问能力

### Requirement: 会话模型与思考强度设置

Web SHALL 在聊天区同一配置面板内提供模型和思考强度选择，选项取自与 TUI 相同的 Pi 能力列表，一次确认提交当前会话配置。面板 SHALL 显示当前值、切换模型后的有效强度及“从下一次请求生效”说明；输入卡片工具行展示服务端确认值。设置页的用户级凭据与会话级模型配置 MUST 清楚区分。

#### Scenario: 切换和取消

- **WHEN** 用户从 Flash low 选择 Pro
- **THEN** 草稿强度按 Pi 调整为 high 并显示，确认后模型和强度一并生效；取消不改变会话

#### Scenario: 双端一致

- **WHEN** Pi 1.1.0 下选择 Flash 或 Pro，或 TUI 修改当前会话
- **THEN** Flash 提供 off/low/high/max、Pro 提供 off/high/max；Web 同步实际生效配置，不提供其他档位

#### Scenario: 切换会话与请求失败

- **WHEN** 配置面板打开期间切换会话，或提交失败、返回过期响应
- **THEN** 不向新会话误提交旧草稿，不让旧响应覆盖新会话；失败保持实际生效值并提示重试

#### Scenario: 面板访问

- **WHEN** 用户通过键盘或触屏从输入卡片工具行打开模型面板
- **THEN** 可完成选择和确认，Escape 可取消并恢复焦点，面板在小屏中不越界或遮挡无法访问的操作

### Requirement: Web 压缩命令与状态

Web 输入框 SHALL 支持 `/compact [附加要求]`，输入斜杠时提供可用命令菜单，另提供可发现的压缩菜单入口。命令 MUST 在普通消息忙碌拦截之前解析，不发送为聊天文字。输入区 SHALL 展示独立压缩状态及真实结果，保持编辑能力，不用阻断式弹窗或虚假百分比表示后台压缩。

#### Scenario: 键盘和触屏命令

- **WHEN** 用户用方向键、Enter、Escape 或触屏选择 /compact
- **THEN** 可选择、取消并执行，输入法组字不误触发；附加要求作为操作参数，命令不更新会话排序

#### Scenario: 运行与晚到结果

- **WHEN** 会话正在回答或用户在压缩期间切换会话
- **THEN** 仍可手动压缩，后台压缩不额外阻塞正常对话；旧结果只更新原会话，不清除新草稿

### Requirement: Web 图片附件交互

Web SHALL 提供输入框附件按钮、多图选择、拖放与剪贴板粘贴。添加后 SHALL 在输入框上方显示缩略图、移除入口、处理状态与失败反馈，不自动发送。用户可发送仅图片或图文消息；普通文本粘贴保持文字。失败 MUST 保留草稿，服务端受理后才清除对应附件。

#### Scenario: 添加与重试

- **WHEN** 用户选择、拖入或粘贴图片，部分图片处理失败
- **THEN** 成功和失败项分别可见，用户可移除失败项或重试，不静默跳过失败附件发送余下内容

#### Scenario: 模型与会话变更

- **WHEN** 有附件时切换至 Pro 或其他会话
- **THEN** Pro 下保留并提示处理附件，草稿按会话隔离；异步处理、上传或发送结果不影响新会话

### Requirement: 图片预览与响应式访问

Web SHALL 在历史中显示图片缩略图，按需加载大图并提供关闭入口。附件、命令菜单和预览 SHALL 遵循全站统一的蓝粉白主题，支持键盘和触屏，且在 1440、1024、768、375、1920、2560 像素宽度下可访问、不横向溢出。预览关闭后恢复焦点，移除和关闭操作有明确可访问名称。

#### Scenario: 大图与菜单

- **WHEN** 用户打开大图、滚动长附件列表或在小屏展开命令菜单
- **THEN** 操作不被遮挡，模态预览约束焦点并支持 Escape，菜单取消恢复编辑且不误发消息

### Requirement: Web 工作区引用候选

Web SHALL 在输入框有效词边界输入 @ 时展示当前工作区文件候选，支持名称搜索、子目录定位、方向键选择、Enter/Tab 确认和触屏点击；Esc 关闭且保留输入。选择 MUST 仅替换光标所在引用片段，不误发消息、不抢走输入焦点。邮箱中的 @ 和输入法组字 MUST NOT 误触发选择或发送。Windows、macOS 和 Linux 宿主 SHALL 均支持文件、目录和嵌套路径候选，引用路径统一使用 `/`，不得因宿主分隔符差异丢弃有效候选。

#### Scenario: 选择与继续编辑

- **WHEN** 用户在一段文字中输入 @，选择带空格的文件或目录
- **THEN** 插入准确引用并保留前后文字与光标，目录可继续浏览，关闭候选后可发送目录引用；文件和目录遵循统一引用语义

#### Scenario: 输入法与普通文本

- **WHEN** 用户输入邮箱、使用中文输入法确认文字或按 Esc 关闭候选
- **THEN** 邮箱保持普通文本，组字确认不选择候选或发送消息，取消不清空草稿

#### Scenario: Windows 文件与目录

- **WHEN** Windows 宿主已安装 fd，工作区包含未被忽略的 `README.md`、`src` 目录和 `src/index.ts`，用户输入 `@`
- **THEN** 候选包含该文件和目录；选择目录插入 `@src/`，继续定位可选择 `src/index.ts`

#### Scenario: 搜索嵌套文件与空格目录

- **WHEN** 用户通过名称搜索位于多级目录或带空格目录中的文件
- **THEN** Windows、macOS 和 Linux 均返回匹配的工作区内候选，插入的路径使用 `/` 并正确引用空格

### Requirement: Web 候选呈现与生命周期

候选面板 SHALL 遵循全站统一的蓝粉白主题，显示类型、名称和父路径，区分加载、无结果、缺少依赖、失败与候选过多。面板 SHALL 限高滚动且不遮挡输入或越出视口，提供可访问名称和选中状态，支持键盘和触屏。查询、图片处理和草稿 MUST 绑定原工作区及会话；关闭或切换后旧响应不得恢复面板或修改新草稿。

#### Scenario: 响应式与焦点

- **WHEN** 用户在 1440、1024、768、375 像素宽度下浏览长路径及长列表，或移动键盘缩小可视区域
- **THEN** 面板保持可操作、无横向溢出，选中项可见且辅助技术可识别；焦点保持在编辑流程中，Tab 确认当前候选，Shift+Tab 仍可离开输入框；文件与斜杠命令弹层样式统一且宽度与输入框对齐

#### Scenario: 异步和重连

- **WHEN** 查询未完成时用户修改引用、关闭候选、切换工作区或连接断开后恢复
- **THEN** 旧查询被取消且不覆盖新状态，草稿保留；重新查询使用当前工作区，不自动重新打开已关闭面板

#### Scenario: 图片选择

- **WHEN** 用户选择宿主工作区图片
- **THEN** 通过绑定原会话的图片流程显示附件、处理状态与错误，不将浏览器本地文件选择器误作宿主文件查询；失败保留引用和草稿

### Requirement: Web 技能命令菜单

Web composer SHALL 在输入 `/`、`/skill` 或 `/skill:` 前缀时于命令菜单中列出当前会话的技能；条目 SHALL 显示名称、单行截断的简述与来源级别标记，内置级技能 MUST 显示可辨识的「内置」标记；不展示完整描述全文。选中后填入 `/skill:<name> `；提交时 MUST 原样发送，展开由 core 完成。

#### Scenario: 菜单列出技能

- **WHEN** 用户在输入框键入 `/skill` 或 `/skill:`
- **THEN** 菜单列出当前会话的技能条目，每条为名称加一行截断简述

#### Scenario: 内置技能标记

- **WHEN** 菜单中包含内置级技能
- **THEN** 该条目显示「内置」标记，与用户级/项目级技能可区分

#### Scenario: 选中填入

- **WHEN** 用户通过方向键、鼠标、Enter 或 Tab 选中某技能条目
- **THEN** 输入框变为 `/skill:<name> `，等待参数输入

#### Scenario: 原样提交

- **WHEN** 用户提交 `/skill:pdf 参数`
- **THEN** 原文发送给 gateway，不在客户端展开

#### Scenario: 加载与连接恢复

- **WHEN** 技能列表正在加载、加载失败、没有匹配项，或会话连接恢复
- **THEN** 菜单显示对应反馈而非消失；连接就绪或重新打开菜单后重新查询，旧会话响应不覆盖新会话

#### Scenario: 空工作区

- **WHEN** 当前工作区尚未建立会话且用户查询技能
- **THEN** 菜单提示先新建会话，不伪造空技能列表

### Requirement: 输入区可访问性与层级

Web 输入区 SHALL 为消息输入框提供不依赖 placeholder 的可访问名称；附件区、错误与提示行、建议弹层和操作按钮组 SHALL 在输入卡片内有清晰一致的视觉层级与间距。浮动操作入口 MUST NOT 遮挡消息或工具输出正文。触屏设备上输入卡片的操作按钮 SHALL 提供不小于 44px 的触控目标。

#### Scenario: 输入框可访问名称

- **WHEN** 辅助技术聚焦于消息输入框
- **THEN** 朗读出描述用途的名称，即使 placeholder 已因输入而消失

#### Scenario: 浮动入口不遮挡

- **WHEN** 用户向上滚动离开底部，出现回到底部浮动按钮
- **THEN** 按钮位于不遮盖消息与工具输出正文的位置，或其占位已计入布局留白

#### Scenario: 触屏目标尺寸

- **WHEN** 用户在触屏设备上操作输入卡片
- **THEN** 附件、命令菜单、发送与停止按钮的触控目标不小于 44px，相邻控件不因目标过近而误触发

### Requirement: 工具调用状态可辨识

工具调用卡片 SHALL 以图标和颜色双重手段区分进行中、成功与失败状态；失败态 MUST NOT 仅依赖细微边框色差，且无需展开即可辨识。

#### Scenario: 失败与成功并列可区分

- **WHEN** 同一会话中存在成功与失败的工具调用卡片
- **THEN** 用户在折叠状态下即可通过图标与显著色彩差异区分两者

#### Scenario: 非色彩线索

- **WHEN** 用户在灰度显示或色弱模拟条件下查看工具卡片
- **THEN** 状态仍可凭图标或文字线索区分

### Requirement: Web 文件补全依赖安装引导

宿主未找到可执行 fd 或 fdfind 时，Web SHALL 在 @ 候选面板展示明确的缺少依赖提示与宿主平台对应的安装指导，该提示 MUST 能通过远程服务到达浏览器，不得退化为内部服务错误或无匹配结果。提示 SHALL 明确在运行 neko 的电脑上安装，并提示安装后重新打开终端并重启 neko。系统 MUST NOT 自动安装工具，提示 MUST 保留草稿且不阻止关闭候选后发送普通消息。

#### Scenario: Windows 缺少依赖

- **WHEN** gateway 运行在 Windows 且找不到 fd/fdfind，用户触发 @ 补全
- **THEN** 面板显示缺少依赖及 `winget install sharkdp.fd`

#### Scenario: macOS 缺少依赖

- **WHEN** gateway 运行在 macOS 且找不到 fd/fdfind，用户触发 @ 补全
- **THEN** 面板显示缺少依赖及 `brew install fd`

#### Scenario: Linux 与其他宿主

- **WHEN** gateway 运行在 Linux 且找不到 fd/fdfind
- **THEN** 面板提供明确标注 Debian/Ubuntu 的 `sudo apt install fd-find` 示例与官方安装文档地址，不声称 apt 适用于全部 Linux；其他未知宿主平台提供通用安装提示与官方安装文档地址

#### Scenario: 浏览器与宿主平台不同

- **WHEN** 用户通过 Windows 浏览器连接 macOS gateway，且 gateway 找不到 fd/fdfind
- **THEN** 显示 macOS 的安装命令，不根据浏览器平台显示 winget

#### Scenario: fdfind 已可用

- **WHEN** 宿主 PATH 只有可执行 fdfind，没有 fd
- **THEN** 补全正常搜索，不提示缺少依赖，不要求建立 fd 别名

#### Scenario: 安装后恢复与草稿保留

- **WHEN** 用户看到缺少依赖提示并关闭候选，随后安装工具、重新打开终端并重启 neko
- **THEN** 关闭候选时原草稿保留且可发送普通消息；重启后新查询在依赖可用时正常返回候选

#### Scenario: 其他错误不误报依赖缺失

- **WHEN** fd 已找到，但搜索超时、执行失败或请求被取消
- **THEN** 不显示安装依赖提示；取消或工作区切换后的旧反馈不得恢复候选面板

### Requirement: 聊天区分层宽度

聊天区消息列 SHALL 按视口宽度分档抬升列宽上限，档位与宽度值 MUST 来自脚本与样式间单一来源的布局 token。用户消息气泡 SHALL 保持有上限的紧凑宽度；助手回答气泡 SHALL 允许使用完整列宽；工具调用卡片与代码块 SHALL 与消息列同宽，左右边缘与气泡对齐。各档位下页面 MUST NOT 横向溢出。

#### Scenario: 窄屏基准

- **WHEN** 视口宽度不超过 1280px
- **THEN** 消息列保持基准列宽 48rem，用户气泡不超过列宽的 75%

#### Scenario: 宽屏抬升

- **WHEN** 视口宽度达到 1920px 或更高档位
- **THEN** 消息列宽按分档抬升，聊天区两侧留白占比随视口增大而下降

#### Scenario: 内容宽度对齐

- **WHEN** 助手回答包含工具调用卡片或代码块
- **THEN** 工具卡与代码块与消息列同宽，左右边缘与助手气泡对齐，不突破列宽

#### Scenario: 宽屏不溢出

- **WHEN** 在 1920 或 2560 像素宽度下浏览长会话
- **THEN** 页面无横向滚动，回到底部入口、遥测指示与输入卡片均可正常访问

### Requirement: 输入卡片与遥测呈现

Web 输入区 SHALL 呈现为单一浮动卡片：附件列表、消息输入框与工具行（附件、模型与思考强度入口、发送/停止）同处一个卡片容器。瞬态状态（忙碌、压缩相位、错误）SHALL 常驻可见；稳态遥测（输入/输出 token 与成本）SHALL 默认收起，悬停或聚焦时展开。忙碌时卡片 SHALL 给出环境态视觉反馈，并在 prefers-reduced-motion 下降级为静态。连接状态 SHALL 保留在顶栏。

#### Scenario: 模型入口在卡片内

- **WHEN** 用户想切换模型或思考强度
- **THEN** 从输入卡片工具行打开配置面板，入口与输入焦点相邻，提交后卡片展示服务端确认值

#### Scenario: 遥测悬停展开

- **WHEN** 用户悬停或键盘聚焦遥测指示
- **THEN** 展开输入/输出 token 与成本详情；移开或失焦后收起，不收起瞬态忙碌与压缩状态

#### Scenario: 瞬态状态常驻可见

- **WHEN** 会话正在回答或正在压缩上下文
- **THEN** 输入卡片上直接可见对应状态，不依赖悬停，失败状态以强调色呈现

#### Scenario: 动效降级

- **WHEN** 系统开启 prefers-reduced-motion
- **THEN** 忙碌环境特效呈静态提示，无位移或循环动画，状态信息不丢失

#### Scenario: 上下文用量指示

- **WHEN** 最近一次回答的上下文用量已知
- **THEN** 输入卡片显示用量占比指示，接近上限时以强调色呈现，详尽的 token 数值经悬停或聚焦查看

### Requirement: Web 技能调用消息展示

Web SHALL 将以 `<skill>` 块开头的用户消息渲染为工具卡风格的折叠卡片：卡片显示技能图标、`skill:<name>` 名称与截断的来源路径，默认折叠，点击展开查看技能正文（等宽、限高滚动）。`</skill>` 之后的参数文本 SHALL 仍以普通用户消息文本显示。无法完整解析的同类文本 MUST 回退为原样渲染，不得丢失内容。卡片样式 SHALL 遵循全站统一的蓝粉白 design tokens。

#### Scenario: 折叠卡片

- **WHEN** 用户通过 `/skill:pdf 总结它` 提交且技能命中展开
- **THEN** 该用户消息显示为折叠的技能卡片（图标 + `skill:pdf` + 来源路径），正文不铺开

#### Scenario: 展开正文

- **WHEN** 用户点击技能卡片
- **THEN** 卡片展开显示技能正文，再次点击折叠

#### Scenario: 参数仍可见

- **WHEN** 技能调用带有参数
- **THEN** 参数文本在卡片外以普通用户消息样式显示

#### Scenario: 解析失败回退

- **WHEN** 用户消息以 `<skill` 开头但不符合展开格式（如手工输入、未命中透传）
- **THEN** 消息按原样纯文本渲染，内容完整可见

### Requirement: Web 技能市场页与分组浏览

Web SHALL 提供技能市场页，设置区以统一侧栏菜单提供可发现入口：密钥与技能市场为侧栏选项，两页共用外壳、可互相切换，市场页可导航回聊天。市场页 SHALL 按分类或来源对技能分组展示（用户可切换两种分组方式），提供关键词搜索；卡片 SHALL 显示名称、简述、来源、版本与大小，并以可辨识标记区分项目级/用户级已安装与内置技能。分组、搜索与卡片样式 SHALL 遵循全站统一的蓝粉白 design tokens。市场不可达 SHALL 显示错误态与重试入口。

#### Scenario: 进入市场页

- **WHEN** 用户在设置侧栏点击技能市场选项
- **THEN** 切换到市场页，显示分组的市场技能卡片，侧栏保持可见

#### Scenario: 切换分组方式

- **WHEN** 用户将分组从按分类切换为按来源
- **THEN** 同一批技能按来源重新分组，各组显示数量

#### Scenario: 安装状态标记

- **WHEN** 技能已安装到用户级或项目级，或为内置技能
- **THEN** 卡片显示对应级别标记，内置技能显示「内置」

#### Scenario: 市场不可达

- **WHEN** 市场请求失败
- **THEN** 页面显示错误说明与重试按钮，不显示空分组

### Requirement: Web 技能详情与预览

市场页 SHALL 提供技能详情视图：完整描述、元数据（分类、来源、版本、大小、SHA-256 摘要、上传时间、许可证中可用项）与两级安装状态；并提供预览入口查看 SKILL.md 正文与包内文件清单。详情视图桌面端以抽屉呈现，移动端为全屏弹层；预览正文 SHALL 以站内 Markdown 渲染。

#### Scenario: 查看详情

- **WHEN** 用户点击技能卡片
- **THEN** 打开详情视图，显示完整描述、元数据与项目级/用户级安装状态

#### Scenario: 预览正文

- **WHEN** 用户在详情中打开预览
- **THEN** 显示渲染后的 SKILL.md 正文与文件清单，本地无写入

### Requirement: Web 市场安装与卸载确认

详情视图 SHALL 提供「安装到用户级」「安装到项目级」操作；目标级已有同名技能时 SHALL 先弹明确确认（说明覆盖将丢失本地版本），确认后才执行覆盖安装；项目级有同名而安装到用户级时 SHALL 提示该安装不生效。已安装技能 SHALL 提供卸载操作，卸载前弹明确确认；内置技能不显示安装/卸载操作。操作进行中 SHALL 有加载态，结果以成功/失败反馈呈现。

#### Scenario: 覆盖确认

- **WHEN** 用户级已存在某技能，用户再次安装到用户级
- **THEN** 先显示覆盖确认对话框，确认后才写入

#### Scenario: 遮蔽提示

- **WHEN** 项目级已有同名技能，用户安装到用户级
- **THEN** 安装前提示项目级优先、此安装不生效

#### Scenario: 卸载确认

- **WHEN** 用户卸载用户级技能
- **THEN** 先显示卸载确认，确认后删除并在卡片与详情中更新状态

#### Scenario: 内置技能只读

- **WHEN** 详情中的技能为内置级
- **THEN** 不提供安装与卸载按钮

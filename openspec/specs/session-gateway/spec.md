# session-gateway Specification

## Purpose

本地会话网关：托管持久会话并向多个前端提供统一的连接、attach 与服务路由，使终端和 Web 可同时对同一会话工作。

## Requirements

### Requirement: 会话目录
系统 SHALL 维护会话目录（创建、列出、删除会话），目录变化 MUST 实时推送给已连接的前端。每个条目 SHALL 包含持久化的工作区、标题、首问摘要、创建时间、最近消息时间与最近使用信息，并提供会话模型和运行状态，以支持前端展示、筛选和恢复。目录保持全局可见，工作区筛选不构成权限隔离。

#### Scenario: 新会话广播
- **WHEN** 任一前端创建会话
- **THEN** 所有已连接前端在目录更新中收到该会话及其工作区

#### Scenario: 最近使用更新
- **WHEN** 会话被成功激活或接受用户输入
- **THEN** 最近使用信息被持久更新并推送，网关重启后仍可据此排序；仅后台输出不改变最近使用顺序；最近使用时间与最近消息时间分别维护

### Requirement: 多前端 attach

系统 SHALL 允许多个前端同时 attach 同一会话，每个 attachment 有服务端分配的标识；重复 attach MUST 幂等。

#### Scenario: 双前端同步

- **WHEN** 终端和 Web 同时 attach 同一会话，终端提交一条输入
- **THEN** 两个前端都收到该输入及后续的流式回答

#### Scenario: 断连释放

- **WHEN** 某前端连接断开
- **THEN** 其 attachment 在已受理调用结算后释放，会话本身与其他 attachment 不受影响

### Requirement: 传输支持

网关 SHALL 同时提供 Unix socket（供终端等本地客户端）与 WebSocket（供浏览器）两种传输。

#### Scenario: 浏览器连接

- **WHEN** Web 前端通过 WebSocket 连接网关
- **THEN** 可完成握手、会话列表查询与会话 attach

### Requirement: 多工作区目录一致性
网关 SHALL 在同一存储中托管多个工作区会话。会话投影的工作目录 MUST 来自该会话保存的工作区，不能使用网关进程目录覆盖。新建会话省略目录时 SHALL 使用网关启动时确定的默认工作区。

#### Scenario: 复用另一目录的网关
- **WHEN** 从工作区 B 启动的 TUI 连接启动于 A 的网关并指定 B 创建会话
- **THEN** 新会话的工具默认目录、目录条目与聊天投影均为 B，A 中会话保持不变

#### Scenario: Web 同时连接
- **WHEN** Web 与 TUI attach 同一会话
- **THEN** 两者收到相同工作区与会话状态，Web 仍可浏览全局会话目录

### Requirement: 最近消息时间与目录更新

系统 SHALL 在接受新的用户输入或成功提交完整回答时持久更新最近消息时间。打开会话、重复请求、流式片段、工具输出、标题生成和配置修改 MUST NOT 更新该时间。会话创建但无消息时 SHALL 使用创建时间作为列表排序回退；时间相同按会话 ID 稳定倒序。目录 SHALL 同步标题、消息时间、模型与运行状态变化，不依赖会话保持前端连接。

#### Scenario: 查看旧会话

- **WHEN** 用户打开较早的会话但没有发送新输入
- **THEN** 最近使用时间更新，最近消息时间保持原值，按消息时间排列的列表顺序不变

#### Scenario: 后台回答完成

- **WHEN** 用户切到其他会话后，原会话成功完成回答
- **THEN** 原会话最近消息时间更新并广播；流式期间不逐片段更新排序

#### Scenario: 重复提交与失败

- **WHEN** 相同请求标识被重复提交，或回答失败、取消
- **THEN** 重复输入不重复更新时间，失败或取消不伪造成功回答时间；已接受的新输入时间保留

#### Scenario: 空会话与时间相同

- **WHEN** 列表包含没有消息的新会话或消息时间相同的会话
- **THEN** 空会话按创建时间参与排序，同时间会话按 ID 稳定倒序，两端顺序一致

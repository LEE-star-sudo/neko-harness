# session-gateway Specification

## Purpose

本地会话网关：托管持久会话并向多个前端提供统一的连接、attach 与服务路由，使终端和 Web 可同时对同一会话工作。

## Requirements

### Requirement: 会话目录
系统 SHALL 维护会话目录（创建、列出、删除会话），目录变化 MUST 实时推送给已连接的前端。每个条目 SHALL 包含持久化的工作区、标题、首问摘要、创建时间、最近消息时间与最近使用信息，并提供会话模型和运行状态，以支持前端展示、筛选和恢复。目录保持全局可见，工作区筛选不构成权限隔离。

#### Scenario: 新会话广播
- **WHEN** 任一前端创建会话
- **THEN** 所有已连接前端在目录更新中收到该会话及其工作区

#### Scenario: 最近使用更新
- **WHEN** 会话被成功激活或接受用户输入
- **THEN** 最近使用信息被持久更新并推送，网关重启后仍可据此排序；仅后台输出不改变最近使用顺序；最近使用时间与最近消息时间分别维护

### Requirement: 多前端 attach

系统 SHALL 允许多个前端同时 attach 同一会话，每个 attachment 有服务端分配的标识；重复 attach MUST 幂等。attach 成功 SHALL 表示当前会话首个完整视图已可用；切换或 detach 后旧 attachment MUST 不再接受新会话操作。连接私有的未提交图片与请求资源 MUST 与其他 attachment 隔离，共享会话运行不随前端释放而终止。

#### Scenario: 双前端同步

- **WHEN** 终端和 Web 同时 attach 同一会话，终端提交一条输入
- **THEN** 两个前端都收到该输入及后续的流式回答

#### Scenario: 断连释放

- **WHEN** 某前端连接断开
- **THEN** 其 attachment 在已受理调用结算后释放，会话本身与其他 attachment 不受影响；未使用图片资源被回收，可取消的查询停止

#### Scenario: 首次状态与重复 attach

- **WHEN** 客户端 attach 到一个会话，或在同一连接重复 attach 同一会话
- **THEN** 成功返回时首个视图已可读取；重复 attach 保持相同 attachment 标识，不重复创建共享会话观察资源

#### Scenario: 旧会话引用失效

- **WHEN** 客户端切换会话、detach，或原会话已归档后仍使用旧引用提交输入、修改配置或操作图片
- **THEN** 操作明确失败，不发送到旧会话或新会话，迟到状态不覆盖新选择

#### Scenario: 上传隔离

- **WHEN** 两个客户端 attach 同一会话，一端尝试使用另一端尚未提交的图片上传引用
- **THEN** 引用被拒绝；关闭或切换其中一端不会回收另一端的上传或停止共享会话回答

### Requirement: 传输支持

网关 SHALL 按平台提供本地传输：macOS/Linux 同时提供 Unix socket（供终端等本地客户端）与 WebSocket（供浏览器）；Windows 不提供 Unix socket，仅提供 WebSocket。所有平台上已启用的传输 MUST 提供完全相同的服务契约、输入输出校验和取消语义。新版客户端 SHALL 校验目标网关身份，不支持旧版协议回退；无效帧与超限缓冲 MUST 有界处理而不影响其他连接。

#### Scenario: 浏览器连接

- **WHEN** Web 前端通过 WebSocket 连接网关
- **THEN** 可完成握手、会话列表查询与会话 attach

#### Scenario: Windows 本地客户端连接

- **WHEN** TUI 在 Windows 上连接网关
- **THEN** 通过 WebSocket 完成握手与会话 attach，不尝试 Unix socket

#### Scenario: POSIX 双传输不变

- **WHEN** 网关运行于 macOS/Linux
- **THEN** Unix socket 与 WebSocket 同时可用，已有客户端业务操作保持一致

#### Scenario: 网关身份不匹配

- **WHEN** 客户端连接到身份与发现结果不同的网关
- **THEN** 连接被明确拒绝，不读取或提交该网关的会话内容

#### Scenario: 无效帧与慢连接

- **WHEN** 某连接发送无法解析的帧、超过单帧限制，或发送缓冲超过上限
- **THEN** 只关闭该连接并释放相关资源，不无限累积字节或阻塞其他客户端

#### Scenario: 活跃实例与遗留 socket

- **WHEN** 新网关尝试使用已占用的 Unix socket 或端口，或遇到已无监听者的遗留 socket
- **THEN** 活跃实例占用时拒绝启动并给出可操作提示，仅对确认已无监听者的遗留 socket 接管

### Requirement: 多工作区目录一致性
网关 SHALL 在同一存储中托管多个工作区会话。会话投影的工作目录 MUST 来自该会话保存的工作区，不能使用网关进程目录覆盖。新建会话省略目录时 SHALL 使用网关启动时确定的默认工作区。

#### Scenario: 复用另一目录的网关
- **WHEN** 从工作区 B 启动的 TUI 连接启动于 A 的网关并指定 B 创建会话
- **THEN** 新会话的工具默认目录、目录条目与聊天投影均为 B，A 中会话保持不变

#### Scenario: Web 同时连接
- **WHEN** Web 与 TUI attach 同一会话
- **THEN** 两者收到相同工作区与会话状态，Web 仍可浏览全局会话目录

### Requirement: 最近消息时间与目录更新

系统 SHALL 在接受新的用户输入或成功提交完整回答时持久更新最近消息时间。打开会话、重复请求、流式片段、工具输出、标题生成和配置修改 MUST NOT 更新该时间。会话创建但无消息时 SHALL 使用创建时间作为列表排序回退；时间相同按会话 ID 稳定倒序。目录 SHALL 同步标题、消息时间、模型与运行状态变化，不依赖会话保持前端连接。

#### Scenario: 查看旧会话

- **WHEN** 用户打开较早的会话但没有发送新输入
- **THEN** 最近使用时间更新，最近消息时间保持原值，按消息时间排列的列表顺序不变

#### Scenario: 后台回答完成

- **WHEN** 用户切到其他会话后，原会话成功完成回答
- **THEN** 原会话最近消息时间更新并广播；流式期间不逐片段更新排序

#### Scenario: 重复提交与失败

- **WHEN** 相同请求标识被重复提交，或回答失败、取消
- **THEN** 重复输入不重复更新时间，失败或取消不伪造成功回答时间；已接受的新输入时间保留

#### Scenario: 空会话与时间相同

- **WHEN** 列表包含没有消息的新会话或消息时间相同的会话
- **THEN** 空会话按创建时间参与排序，同时间会话按 ID 稳定倒序，两端顺序一致

### Requirement: 凭据配置与同步

网关 SHALL 为 TUI/Web 提供服务器级凭据状态订阅、保存和移除能力，按 provider 分别管理且无需 attach 会话。每个 provider 的状态 SHALL 包含已保存凭据是否存在、网关环境变量是否配置及生效来源。任一 provider 变更持久化成功后 SHALL 通知所有已连接前端，断线重连 SHALL 恢复最新状态；响应和广播 MUST NOT 包含密钥。

#### Scenario: 双端配置

- **WHEN** Web 保存或移除某 provider 的 Key 且 TUI 已连接
- **THEN** 两端收到相同新状态，后续请求使用同一凭据来源，无需重启或切换会话

#### Scenario: 无会话与重连

- **WHEN** 未 attach 会话的客户端打开设置，或配置期间断线后重连
- **THEN** 可读取并管理各 provider 凭据，重连显示服务端最终状态，不因旧响应覆盖新状态

#### Scenario: 并发和失败

- **WHEN** 两端同时修改凭据，或某次持久化失败
- **THEN** 修改按服务端顺序处理并发布一致状态；失败操作不发布成功状态，错误不回显提交的 Key

### Requirement: 会话压缩控制与同步

网关 SHALL 提供会话级手动压缩及可恢复的压缩状态，独立表达回答运行与压缩运行，包含触发原因、是否阻塞、重试及实际结果。同一会话已有压缩时 SHALL 避免重复手动启动。客户端断开 MUST 不导致任务重复或丢失；状态和结果必须绑定原会话。

#### Scenario: 双端并发与重连

- **WHEN** TUI 与 Web 同时请求同一会话压缩，随后一端重连
- **THEN** 不创建重复的手动任务，两端恢复相同实际状态；后台压缩不被错误表示为回答已停止

#### Scenario: 失败和迟到结果

- **WHEN** 压缩失败、中止、无需执行或摘要过期，且前端已切换会话
- **THEN** 原会话保留准确结果，不将任务结束统一解释为成功，不污染新会话状态

### Requirement: 有界图片传输与预览

网关 SHALL 在所有已启用的传输上提供相同的图片提交与按需读取能力；图片与文字合为一次会话输入。状态投影 SHALL 仅携带有界附件描述，图片数据按需取得，不随流式增量重复广播。图片读取 MUST 校验会话、条目和内容位置，不允许将预览请求用作任意宿主路径读取。

#### Scenario: 大图与慢客户端

- **WHEN** 用户提交多张图片或慢客户端查看图片历史
- **THEN** 传输按已公布限制分块并限制并发，不通过无限增大帧或缓冲上限规避问题，文字流和其他客户端仍可工作

#### Scenario: 未完成上传与断线

- **WHEN** 上传后尚未提交就断线，或提交确认丢失后重试
- **THEN** 未使用的临时数据可回收，已受理消息通过请求标识恢复；不出现半条消息或重复消息

#### Scenario: 非当前会话与失效引用

- **WHEN** 读取合法历史附件或请求不属于指定会话的附件
- **THEN** 前者返回原图片，后者明确失败；错误不泄露无关文件内容

### Requirement: 工作区文件查询服务

网关 SHALL 提供工作区文件候选查询，以已登记的工作区身份解析根目录，只返回名称、相对路径、类型及查询状态，不返回文件正文。查询 MUST 与添加工作区的宿主目录浏览分离，支持无会话的工作区，并遵循工作区文件候选规则。取消或客户端断连 SHALL 停止对应查询，不影响其他客户端与会话任务。

#### Scenario: 根目录解析

- **WHEN** Web 在 B 查询文件而网关启动于 A，或 B 尚无会话
- **THEN** 查询只使用已登记的 B；未知工作区、越界输入和失效目录明确失败，不采用 A 作为回退

#### Scenario: 取消与隔离

- **WHEN** 用户继续输入、关闭候选或切换工作区，旧查询尚未完成
- **THEN** 客户端取消旧请求并忽略晚到结果，服务端终止该查询资源，其他客户端的查询和回答继续运行

#### Scenario: 服务能力与错误

- **WHEN** 宿主缺少文件发现依赖、查询超时或候选达到上限
- **THEN** 返回可区分的不可用、超时或有界结果状态，前端提供安装提示、重试或缩小范围指引，不将失败显示为无匹配

### Requirement: 会话技能列表服务

会话级聊天服务 SHALL 提供 `skills()` 方法，返回当前会话可用的技能列表（name、description、SKILL.md 绝对路径），供前端补全使用；该列表 MUST 包含禁用模型调用的技能，并随技能文件变化更新。

#### Scenario: 前端拉取技能

- **WHEN** 已 attach 会话的前端调用 `skills()`
- **THEN** 返回该会话工作区与用户级目录合并的技能列表

#### Scenario: 技能文件变化

- **WHEN** 会话进行中技能文件新增或修改，前端再次调用 `skills()`
- **THEN** 返回更新后的列表

### Requirement: Windows 网关地址发现

Windows 上网关 SHALL 以随机 WebSocket 端口启动，并将实际 ws 地址写入 `<数据目录>/<serverId>.port` 端口文件，供本机前端发现连接；端口文件 MUST 与 serverId 文件同属数据目录并随网关关闭清理。macOS/Linux MUST NOT 产生端口文件，地址发现机制保持现状。

#### Scenario: Windows 启动与发现

- **WHEN** 网关或前端在 Windows 上拉起新网关
- **THEN** 网关监听随机端口、写出端口文件，前端读文件后以 ws 地址连接

#### Scenario: 端口文件清理

- **WHEN** Windows 上的网关正常关闭，或被强杀导致其清理逻辑未执行
- **THEN** 正常关闭时端口文件被移除；强杀残留由拉起方在终止网关进程后补删，仍残留的过期文件以前端连接失败按无活跃网关兜底

#### Scenario: POSIX 无端口文件

- **WHEN** 网关运行于 macOS/Linux
- **THEN** 数据目录中不出现端口文件，前端沿用 Unix socket 发现

### Requirement: 服务边界校验与就绪

网关 SHALL 在远程服务边界校验请求参数、响应和订阅状态，并向 TUI/Web 提供一致的错误语义。服务器级目录、工作区与凭据的初始状态未到达前，客户端 MUST NOT 宣称管理操作已就绪；无效输入 SHALL 在执行业务修改之前拒绝。凭据及工具内部数据 MUST NOT 因错误或状态校验泄露到客户端。

#### Scenario: 无效参数

- **WHEN** 客户端向创建、配置、图片上传或文件查询方法发送类型错误的参数
- **THEN** 请求被明确拒绝，不创建会话、不修改配置、不留下部分上传，连接仍能处理后续有效请求

#### Scenario: 首个订阅状态迟到

- **WHEN** 服务连接建立成功，但目录、工作区或凭据快照仍未到达
- **THEN** 客户端保持加载状态并等待实际快照；超时或断连返回明确错误，不把未到达状态当成空目录或无凭据

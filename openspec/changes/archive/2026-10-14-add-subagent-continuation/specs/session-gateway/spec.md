## MODIFIED Requirements

### Requirement: 子 agent 观察与停止服务
网关 SHALL 提供绑定主会话、按稳定身份去重的子 agent 列表及每轮委派引用、按需连续子会话详情订阅、轮次定位、历史读取、图片读取及绑定当前轮的单独停止能力。详情 SHALL 包含与主会话同类的持久消息和实时调用数据，保留原有错误、截断及图片传输规则；同一子会话在总用量中 SHALL 只汇总一次，详情 SHALL 区分累计与各轮增量。接口 MUST 校验主子归属和目标轮次，不允许借详情句柄提交输入、修改配置或启动新子任务。

#### Scenario: 双端观察
- **WHEN** Web 与 TUI 同时查看同一子 agent，一端停止它
- **THEN** 两端获得相同最终状态及已产生历史，主会话与其他子任务继续按原生语义运行

#### Scenario: 旧引用与越界
- **WHEN** 客户端切换主会话后旧详情返回，或请求不属于该主会话的子会话与图片
- **THEN** 旧响应不覆盖新选择，非法读取或停止被拒绝，不触及无关会话

#### Scenario: 重连与资源释放
- **WHEN** 用户关闭详情、断线或重新连接
- **THEN** 未使用的详情订阅及读取资源释放，执行不中断；重连恢复真实记录而不重新派发任务

#### Scenario: 大量历史
- **WHEN** 子 agent 产生很长工具日志或多个子 agent 同时流式运行
- **THEN** 列表仅推送摘要，详细历史按需有界加载，不每次把所有子会话完整历史广播给所有客户端

#### Scenario: 旧轮停止请求
- **WHEN** 一轮结束后同一子 agent 已开始新轮，而旧客户端提交上一轮停止请求
- **THEN** 返回已结束或失效状态，不把请求重定向到最新轮，不停止新的任务

#### Scenario: 一身份多轮详情
- **WHEN** 两条主委派卡指向同一子 agent 的不同轮次
- **THEN** 可读取同一连续历史并定位各自轮次，列表只有一条身份摘要，总用量不重复累加

### Requirement: 主会话归档与分叉的委派边界
归档主会话 SHALL 先停止所属未完成委派，再隐藏其访问入口；用户分叉主会话 MUST NOT 复制正在执行的委派。分叉历史中的委派卡 SHALL 可只读查看分叉点之前已有的记录，不授予控制原任务的能力，也不把原任务后续活动或成本计为新分叉任务。历史引用 SHALL 按唯一子会话冻结内容与用量；分叉的可接续身份列表不得包含原会话子 agent。

#### Scenario: 归档运行中主会话
- **WHEN** 用户归档仍有运行或排队子任务的主会话
- **THEN** 所属任务结束取消流程后主会话隐藏，不留下继续执行却无法查看的子任务

#### Scenario: 分叉已有委派
- **WHEN** 用户从含委派卡的主会话创建分叉
- **THEN** 历史卡标识为原会话记录，查看仅限分叉点已有内容，不能停止原任务或复制派发

#### Scenario: 原子 agent 接续不污染分叉
- **WHEN** 用户分叉主会话后，原会话继续向既有子 agent 派发后续任务
- **THEN** 分叉历史仍显示冻结内容和费用，不能接续或停止原子 agent；分叉可创建自己的新子 agent

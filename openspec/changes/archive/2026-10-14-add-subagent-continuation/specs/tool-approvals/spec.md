## MODIFIED Requirements

### Requirement: 持久审批与竞争处理
系统 SHALL 持久保存审批身份、操作内容、决定、关联子 agent 和当前委派轮次，提供 pending、allowed、denied、cancelled 状态。接续执行时 SHALL 将新请求关联当前轮而非首个历史委派；相同调用的恢复 SHALL 复用原请求；多端决定 SHALL 原子结算，只有第一次有效决定生效，重复或冲突提交返回已结算状态。审批状态 MUST 与命令运行状态分开表达，允许不代表执行成功。

#### Scenario: 双端同时操作
- **WHEN** Web 允许与 TUI 拒绝同一请求同时到达
- **THEN** 只有一个决定生效，两端最终展示相同结果，不重复执行

#### Scenario: 重连与等待期重启
- **WHEN** 前端断线或 gateway 在等待审批时重启
- **THEN** 重连后仍可处理同一未决请求；已持久保存的决定不会丢失或重复询问

#### Scenario: 接续轮的新命令
- **WHEN** 同一子 agent 在第二轮再次请求第一轮曾获批的相同 Bash 命令
- **THEN** 产生属于第二轮的新审批，原批准不复用；输入区只显示当前未决操作，结果附于该次命令

#### Scenario: 旧轮决定迟到
- **WHEN** 上一轮已停止或结算、下一轮已开始，客户端对旧请求提交决定
- **THEN** 仅返回旧请求最终状态或失效错误，不能授权、取消或更改下一轮的命令

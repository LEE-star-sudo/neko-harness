## MODIFIED Requirements

### Requirement: Web 委派卡片与侧栏
Web SHALL 在主消息流中为每轮任务独立展示角色、任务简称、状态及耗时的委派卡片，并提供右侧子 agent 列表与详情。列表 SHALL 按稳定子 agent 身份去重，单行展示角色、稳定名称和轮数；空闲、排队、运行状态在详情中展示；各轮保留完成、失败、停止状态及报告。停止入口 SHALL 绑定当前活动轮，已结束轮次仍可查看。首次委派可展开侧栏，用户主动关闭后 MUST NOT 因流式更新反复打开。

#### Scenario: 多个子任务
- **WHEN** 主 agent 并行委派多个任务
- **THEN** 主消息流与侧栏分别展示各任务，点击任一卡片定位同一子 agent 的对应轮次详情，失败与停止有文字或图标区分

#### Scenario: 接续和空闲
- **WHEN** 子 agent 第一轮完成并被再次派发任务
- **THEN** 侧栏仍只有同一个身份条目，单行显示角色、稳定名称和 2 轮，不重复显示最近任务摘要或状态行；两张主任务卡保持各自结果，详情显示当前状态，全部轮次结束后显示空闲

#### Scenario: 关闭后的接续
- **WHEN** 用户已关闭子侧栏，同一子 agent 开始接续任务
- **THEN** 只更新状态和已有审批入口，不强制打开侧栏，主输入草稿及附件保留

### Requirement: Web 子 agent 完整可见流程
子 agent 详情 SHALL 按时间顺序展示各轮任务输入、轮次分隔、助手文字、模型实际返回且系统保存的思考内容、全部可见工具调用的参数与输出/结果、图片、错误及最终报告，支持流式更新、展开和历史回看，与主会话内容类型保持一致。完整流程 MUST NOT 被仅有摘要替代；原有截断与省略须可辨识，不补造模型未提供的内容。同一子 agent SHALL 展示连续历史，详情提供累计用量，各轮摘要可查看本轮消耗；未知旧轮增量须明确标注。

#### Scenario: 工具和图片流程
- **WHEN** 子 agent 多轮调用搜索、读取图片、执行命令，期间有失败重试
- **THEN** 用户可逐项查看参数、各次可见结果、图片和失败信息，而非只看到最后一次调用或最终总结

#### Scenario: 历史和滚动
- **WHEN** 用户向上查看子会话历史后出现新输出，随后重新连接
- **THEN** 不强制滚到底部，提供回到底部入口，持久历史恢复且当前流式内容不重复

#### Scenario: 定位旧轮与浏览状态
- **WHEN** 用户点击较早轮次卡片，而同一子 agent 已执行后续轮次
- **THEN** 按需加载定位该轮，保留卡片目标而不误跳到最新任务；后续输出不强制拉回底部，主/子视图会话切换不报错

#### Scenario: 多轮响应式用量
- **WHEN** 用户在 375、768、1440、1920 像素宽度查看含多轮命令的子 agent
- **THEN** 轮次分隔、累计和本轮用量可读且无横向溢出；审批继续只显示未决请求，结果标注在对应命令旁

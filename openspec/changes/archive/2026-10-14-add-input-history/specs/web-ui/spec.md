# Spec Delta

## ADDED Requirements

### Requirement: Web 输入历史浏览

Web 输入框 SHALL 支持用 ↑/↓ 浏览当前会话的输入历史（条目规则见 `input-history`）：输入为空或光标位于输入起点且无选区时，↑ 回填更早一条并将光标置于开头；处于浏览态且光标位于输入末尾时，↓ 回填更新一条并将光标置于末尾；越过最新一条后 SHALL 还原进入浏览前的草稿。除上述条件外 ↑/↓ 保持浏览器默认光标移动。回填 MUST 作为新草稿处理，已选附件保持不变。用户编辑回填文字、发送或切换会话后 MUST 退出浏览态。

#### Scenario: 空输入按 ↑ 回填最近输入

- **WHEN** 输入框为空且会话有历史，用户按 ↑
- **THEN** 输入框回填最近一条已发送输入且光标位于开头，再按 ↑ 依次回填更早的输入，到最早一条后停止，不循环

#### Scenario: ↓ 返回并还原草稿

- **WHEN** 用户先输入未发送草稿并将光标移到起点后按 ↑ 进入历史，再按 ↓ 直至越过最新一条
- **THEN** 输入框还原为进入历史前的草稿内容

#### Scenario: 多行与折行内的光标移动优先

- **WHEN** 输入框含多行或折行文字且光标不在起点（浏览态向下时不在末尾）
- **THEN** ↑/↓ 保持浏览器默认光标移动，不触发历史切换

#### Scenario: 候选菜单与 IME 优先

- **WHEN** 命令菜单或 `@` 文件候选正在显示，或用户处于 IME 组合输入中
- **THEN** ↑/↓ 按原有行为选择候选或操作输入法，不触发历史切换

#### Scenario: 编辑后退出浏览态

- **WHEN** 用户回填某条历史后修改其中文字
- **THEN** 该文字成为当前草稿，随后按 ↓ 不会覆盖它

#### Scenario: 附件不受影响

- **WHEN** 输入框已有待发送图片附件，用户通过 ↑/↓ 回填历史文字
- **THEN** 附件保持不变，回填文字不含图片

#### Scenario: 回填内容可直接发送

- **WHEN** 用户回填一条历史后按 Enter
- **THEN** 该文字作为新消息发送，且不与此前同文字的发送共用同一请求标识

#### Scenario: 无会话或无历史

- **WHEN** 工作区尚未创建会话，或当前会话没有历史时用户按 ↑ 或 ↓
- **THEN** 输入框行为与现状一致

### Requirement: Web 输入历史的会话隔离与同步

Web SHALL 使每个会话拥有独立的历史与浏览态：切换会话时 MUST 显示新会话的历史，未发送草稿保持各会话独立；会话 transcript 出现新的已提交输入时 SHALL 更新历史，使其成为 ↑ 的第一条。正在浏览历史时 MUST NOT 因后台更新改变用户当前看到的回填内容或浏览位置，更新 SHALL 在退出浏览态后生效。

#### Scenario: 切换会话后历史隔离

- **WHEN** 用户在会话 A 浏览历史后切换到会话 B，再按 ↑
- **THEN** 回填的是会话 B 的最近输入，不含会话 A 的内容；切回会话 A 时其未发送草稿仍在

#### Scenario: 发送后立即可回填

- **WHEN** 用户发送一条输入并在其进入 transcript 后清空输入框
- **THEN** 按 ↑ 回填刚发送的那一条

#### Scenario: 浏览中收到更新

- **WHEN** 用户正在浏览历史时，其他前端向同一会话提交了新输入
- **THEN** 当前回填内容与浏览位置不变，退出浏览态后按 ↑ 的第一条为新输入

#### Scenario: 刷新后仍可浏览

- **WHEN** 用户刷新页面并重新打开该会话
- **THEN** 会话 transcript 加载完成后即可通过 ↑ 回填此前的输入

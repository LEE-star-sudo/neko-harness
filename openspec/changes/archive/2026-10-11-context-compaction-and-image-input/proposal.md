# Proposal

## Why

pi-durable 已提供默认自动压缩和多模态消息，但 Harness 缺少手动压缩入口、可靠状态展示及图片输入链路。用户需要在 TUI/Web 中处理长会话和图片，同时保持上游运行语义及两端行为一致。

## What Changes

- 明确决策优先级：已安装 pi-durable 1.1.0 的运行和持久化语义优先，其次参考 Pi 的能力与交互，最后才为缺失部分采用主流产品设计；不升级或补丁修改 Pi。
- 两端增加 `/compact [附加要求]`，Web 增加命令补全及可发现的菜单入口；复用默认压缩策略、模型、强度、重试和中止语义。
- 同步显示后台、阻塞、重试及最终压缩结果，区分摘要生成结束与实际应用，不改变最近消息排序。
- 新增独立 `read_image` 扩展工具，按会话工作区解析路径、按模型能力返回图片内容块，不修改内置 read。
- 打通文字与图片混合消息、仅图片消息、持久化、幂等、按需预览与历史恢复；模型切换不得静默丢弃待发图片。
- TUI 参考 Pi 的剪贴板快捷键、路径补全和拖入文件交互，支持图片引用与终端能力驱动的预览；Web 提供附件按钮、拖放、粘贴、缩略图及移除。
- 补齐仅图片首问的命名回退；标题请求仍仅使用文字且关闭思考。

## Capabilities

### New Capabilities

无；在现有能力中增加要求。

### Modified Capabilities

- `agent-runtime`: 原生压缩控制、图片消息持久化、图片处理与独立读取工具。
- `session-gateway`: 会话级压缩状态与结果、附件传输和按需读取。
- `model-providers`: 输入能力与图片限制透传、非视觉模型的发送约束。
- `terminal-ui`: Pi 风格图片输入、压缩命令和状态展示。
- `web-ui`: 主流附件交互、命令入口和压缩状态。
- `session-naming`: 仅图片首问的可辨识名称及文字总结边界。

## Impact

涉及 core 的运行时、工具扩展、消息投影与命名，gateway 契约及 Unix/WS 传输，TUI 编辑器、历史与状态栏，Web 输入框、预览和状态。同步更新中文 README、测试与验收记录。允许为缺失的图片解码/缩放能力增加经过 Bun 验证的精确版本依赖，Pi 包版本保持 1.1.0。

不自研压缩算法、不调整默认阈值、不增加图片描述模型请求、不支持 PDF/音视频或远程图片 URL。本次不删除历史、不做格式迁移；已有纯文本条目继续正常读取。新旧前端与网关不承诺混合版本运行，应一起更新。测试截图和临时图片在验收后清理，不纳入归档。

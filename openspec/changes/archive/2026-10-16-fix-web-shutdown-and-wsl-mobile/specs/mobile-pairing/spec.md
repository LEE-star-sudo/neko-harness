## MODIFIED Requirements

### Requirement: 显式启用局域网入口

移动入口 SHALL 默认关闭，由电脑本机用户显式启用并选择可达局域网地址。系统 SHALL 使用独立的加密入口，只在所选地址上监听，显示实际地址与监听状态，不通过改变现有本地连接的绑定地址开放移动控制。例外：WSL 默认 NAT 网络下按「WSL 下的 Windows 侧中继」要求，监听保持在 WSL 内部地址，由 Windows 侧中继向所选局域网地址提供入口。端口冲突、地址不可用和启动失败 MUST 明确反馈，不显示可用二维码。

#### Scenario: 默认安装与开启
- **WHEN** 用户首次启动电脑端并在本机设置中开启手机访问
- **THEN** 开启前不存在移动监听；开启成功后展示实际局域网地址与扫码入口，本地 TUI/Web 继续工作

#### Scenario: 监听失败
- **WHEN** 选择的网卡地址消失或移动端口被占用
- **THEN** 显示启动失败及检查地址/端口的操作提示，不伪造已启用状态或启动竞争网关

## ADDED Requirements

### Requirement: 监听地址与对外宣告地址分离

系统 SHALL 区分移动入口的监听地址与对外宣告地址：二维码、配对文本、状态展示与候选排序 MUST 使用手机实际连接的宣告地址。在非 WSL 平台两者相同；证书指纹校验不因两者不同而改变。最近接入地址 SHALL 以宣告地址记录。

#### Scenario: 非 WSL 平台行为不变
- **WHEN** 在 macOS、Linux 或 Windows 原生环境启用手机访问
- **THEN** 监听地址等于所选地址，二维码地址与监听地址一致，不启动任何中继

#### Scenario: 宣告地址与证书
- **WHEN** 二维码地址与监听地址不同（WSL 中继）
- **THEN** App 仍以二维码中的证书指纹验证对端，指纹匹配即可配对，不要求证书包含宣告地址

### Requirement: WSL 下的 Windows 侧中继

当 gateway 运行在 WSL 且可调用 Windows 互操作时，手机配对的候选地址 SHALL 为 Windows 侧可供手机直连的局域网 IPv4（排除回环、链路本地、虚拟、WSL 与代理保留网段），而不是 WSL 内部地址。启用时系统 SHALL 在 Windows 侧只在所选地址上启动 TCP 中继，把连接原样转发到 WSL 内的移动监听；该过程 MUST NOT 要求管理员权限、端口映射配置或切换 WSL 网络模式。所选地址已存在于 WSL 自身网卡（镜像网络）时 SHALL 直接监听，不启动中继。

#### Scenario: WSL NAT 下配对
- **WHEN** 用户在 WSL 默认 NAT 网络中启动 neko 并在配对页选择 Windows 局域网地址开启手机访问
- **THEN** 二维码地址为该 Windows 局域网地址与端口，同网段手机扫码后可连接并完成配对，且无需用户修改 Windows 或 WSL 配置

#### Scenario: 镜像网络直连
- **WHEN** WSL 使用 mirrored 网络且所选地址属于 WSL 自身网卡
- **THEN** 直接在该地址监听，不启动 Windows 侧中继

#### Scenario: 互操作不可用
- **WHEN** WSL 内无法调用 Windows 互操作或读不到可用局域网地址
- **THEN** 不展示二维码，说明原因与可行的处理方式（启用互操作或在 Windows 原生运行），不退回展示 WSL 内部地址作为手机可达地址

### Requirement: 中继随手机访问入口关停

Windows 侧中继 SHALL 与手机访问入口同生命周期：用户关闭手机访问、更换地址或端口、gateway 正常退出或被强制结束、拉起 gateway 的前端退出时，中继 MUST 一并停止并释放端口，不残留 Windows 侧进程。再次启用 SHALL 重新建立中继。关停中继 MUST NOT 终止 gateway、其他前端或已受理的会话任务。

#### Scenario: 用户关闭手机访问
- **WHEN** 手机已通过中继连接，用户在电脑端关闭手机访问
- **THEN** 手机断开、中继停止、Windows 侧该端口被释放，电脑端会话任务继续运行

#### Scenario: 网关被强制结束
- **WHEN** gateway 进程在中继运行期间被强制结束（如终止进程）
- **THEN** 中继在短时间内自行退出并释放端口，之后重新启动前端不因端口被占用而失败

#### Scenario: 重新启用
- **WHEN** 手机访问被关闭后再次开启
- **THEN** 重新建立中继并提供当前有效的宣告地址，已配对设备无需重新扫码（证书与地址身份未变）

### Requirement: 中继入口自检与失败反馈

启用手机访问后，系统 SHALL 在展示二维码前验证中继已在宣告地址上就绪且能到达移动监听；验证失败、中继端口被占用、中继启动失败或中继意外退出时 MUST 明确反馈原因，不显示可用二维码，不伪造已启用状态。中继意外退出后系统 SHALL 将入口状态更新为失败，而非继续显示监听中。

#### Scenario: 端口被占用
- **WHEN** 所选 Windows 局域网地址上的移动端口已被其他程序占用
- **THEN** 启用失败并提示更换端口或释放占用，监听与中继均已清理，不留下半启用状态

#### Scenario: 中继运行中异常退出
- **WHEN** 中继在运行期间意外退出
- **THEN** 入口状态变为失败并提示重新启用，已显示的二维码失效，本地聊天不受影响

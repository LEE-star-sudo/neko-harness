# Proposal

## Why

Web UI 聊天区列宽固定为 48rem（768px），气泡再限 75%（576px），在 1920px 及以上宽屏下主区利用率仅 46%→33%，而代码块、diff、表格与工具卡输出恰恰是最需要宽度的内容，被迫在 576px 内频繁横向换行。同时输入区与状态栏是两条割裂的横带：模型选择器远离输入框、稳态遥测（用量/成本）与瞬态状态（busy/压缩）混排在同一行小字里、触屏按钮只有 40px。需要一次布局与输入区的协同重构。

## What Changes

- 聊天区引入**分层宽度**：消息列宽随视口分档抬升（基准 48rem，≥80rem 视口 56rem，≥105rem 视口 64rem）；用户气泡保持 75% 上限，助手气泡放宽至列宽 100%，工具卡/代码块突破气泡限制、使用更宽的"工作列"。
- 输入区重构为**单一浮动输入卡片**：附件、textarea、工具行（附件按钮、模型选择器、发送/停止）合入同一卡片容器；模型选择器从独立状态栏迁入卡片工具行。
- 稳态遥测（输入/输出 tokens、成本）降级为**悬停/聚焦展开**；瞬态状态（busy、压缩相位、错误）保持常驻可见；连接状态维持顶栏不变；独立状态栏行取消。
- 输入卡片增加克制的状态特效：聚焦提升、busy 时卡片边缘流动渐变（`prefers-reduced-motion` 下逐项降级为静态）。
- 触屏设备输入区按钮目标尺寸补足至 44px。
- 布局常量保持脚本/样式单一来源与对拍测试守护，新增的分档 token 纳入同一机制；响应式验证档位在 1440/1024/768/375 之上补 1920/2560。

## Capabilities

### New Capabilities

（无——分层宽度与输入卡片均属于 web-ui 既有职责的演进）

### Modified Capabilities

- `web-ui`:
  - 修改"响应式导航与可访问操作"：布局 token 单一来源的表述扩展到列宽分档，补充宽屏场景。
  - 修改"二次元主题系统"：输入区与用量呈现的表述随浮动输入卡片更新（token 体系不变）。
  - 修改"会话模型与思考强度设置"：服务端确认值的展示位置从状态栏变为输入卡片工具行。
  - 修改"输入区可访问性与层级"：层级结构随输入卡片更新，补触屏目标尺寸要求。
  - 修改"图片预览与响应式访问"：响应式宽度档位补充宽屏验证。
  - 新增"聊天区分层宽度"：视口分档列宽、气泡与工作列宽度分配、宽屏不溢出。
  - 新增"输入卡片与遥测呈现"：浮动卡片结构、瞬态/稳态信息分层、busy 特效与降级。

## Impact

- 代码：`packages/web/src/client/` 下的 `styles.css`（布局 token、卡片样式、动效与降级）、`lib/layout.ts`（分档常量）、`test/layout-tokens.test.ts`（对拍扩展）、`pages/chat-page.tsx`（移除独立 StatusBar 行）、`components/composer.tsx`（卡片结构重构）、`components/status-bar.tsx`（拆解合并）、`components/model-picker.tsx`（迁入工具行）、`components/message-list.tsx`（气泡/工作列类名）。
- 外观行为：宽屏下列宽与气泡宽度变化；模型/用量入口位置变化（用户可见，非数据兼容性问题）。
- 约束：全站 token 体系、WCAG AA 对比度、reduced-motion 降级模式、Web/TUI 功能对等原则均维持不变。
- 不影响：core、gateway、TUI、WebSocket 协议与任何存储格式。

# Spec Delta

## Purpose

为主会话提供模型可维护、用户可跨 Web、TUI 和手机客户端查看的结构化待办列表。列表表达工作进度但不承担任务调度，以会话持久状态为唯一来源，在重连、重启和分叉后保持明确、一致的语义。

## ADDED Requirements

### Requirement: 主会话结构化待办
系统 SHALL 向主 agent 提供 `todo` 工具，支持 `list` 读取与 `replace` 整体替换有序列表。每项 SHALL 包含列表内唯一的稳定 ID、非空内容和 `pending`、`in_progress` 或 `completed` 状态。空列表 SHALL 表示清空。首版 MUST NOT 向子 agent 开放该工具，也不提供用户直接编辑或任务调度功能。

#### Scenario: 建立和更新计划
- **WHEN** 主 agent 提交有效列表，随后用保留的条目 ID 更新状态或顺序
- **THEN** 列表整体更新，三端保留条目身份并显示新的顺序、内容与状态

#### Scenario: 读取和清空
- **WHEN** 主 agent 读取尚无待办的会话，或整体替换为空列表
- **THEN** 返回空列表，不创建示例任务，不影响其他会话

#### Scenario: 子 agent 边界
- **WHEN** explore、plan 或 coder 子 agent 新建、接续或重启恢复
- **THEN** 其可用工具不含 `todo`，不能修改主会话列表

### Requirement: 待办原子性与恢复
待办更新 SHALL 原子持久保存，并在提交后才对外可见。同一次工具调用恢复 MUST NOT 重复更新或把较新列表回滚为旧值。会话重启和上下文压缩 MUST 保留列表；分叉 SHALL 继承分叉点的列表，之后父子列表相互独立。

#### Scenario: 无效列表不部分写入
- **WHEN** 列表包含重复 ID、非法状态、空白内容或超出数量、长度、字节限制
- **THEN** 整次更新明确失败，旧列表保持原样，不静默截断或删除条目

#### Scenario: 更新提交后中断
- **WHEN** 列表已提交但工具结果尚未提交时进程退出，随后重启恢复该调用
- **THEN** 返回该调用原有回执，不再次增加列表版本，也不覆盖该调用之后已保存的列表

#### Scenario: 压缩和分叉
- **WHEN** 有待办的会话被压缩，或在列表发生后续变化后从较早条目分叉
- **THEN** 压缩不改变当前列表；分叉得到较早分叉点的列表，后续父子更新互不影响

### Requirement: 三端待办呈现与能力降级
Web、TUI、Mobile SHALL 提供只读待办入口，展示有序条目、可区分的三态和已完成数/总数，并实时跟随已提交状态。空列表不占用常驻列表空间。缺少此能力的旧网关 SHALL 被识别为不支持，而非支持且为空；客户端不得调用缺失接口或把该差异报告为协议不兼容。

#### Scenario: 跨端同步
- **WHEN** 模型将某项从进行中改为已完成
- **THEN** 三端显示同一进度，不依赖解析工具输出或本地推测

#### Scenario: 查看完整内容
- **WHEN** 待办条目较长或列表超过面板可见区域
- **THEN** 用户可滚动查看完整已保存内容，不撑出页面或遮挡输入、停止和问题回答操作

#### Scenario: 旧网关与断线
- **WHEN** 客户端连接不支持待办的网关，或在已显示列表后断线
- **THEN** 前者隐藏待办入口，后者允许查看已加载内容但明确显示离线，不将本地缓存当作最新状态

### Requirement: 待办资源上限
待办列表 SHALL 最多包含 100 项，每项 ID 最长 64、内容最长 256 个 UTF-16 码元，列表 JSON 的 UTF-8 编码 SHALL 不超过 65,536 字节。ID 与内容 MUST 非空白；超限更新 MUST 在保存前明确拒绝。服务端、工具声明和客户端 SHALL 使用一致的上限。

#### Scenario: 精确边界
- **WHEN** 列表恰好满足每项、总数和总字节上限，或任一项超出上限
- **THEN** 满足所有边界者可保存，任一超限者整次失败；多字节文字按实际 UTF-8 字节计算总预算

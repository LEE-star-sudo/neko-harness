# Design

## Context

动机见 proposal.md。项目锁定 Pi 1.1.0，TUI 的 BoundedEditor 已继承 Pi Editor，CombinedAutocompleteProvider 当前只收到 commands 和 cwd。已安装实现的 @ 查询在缺少 fdPath 时返回空结果；本机传入 fd 后，@、@runtime 和子目录查询均返回候选。Pi 的交互式补全只插入路径；coding-agent 的 CLI @file 全文加载是另一条流程，不应混用。

Web Composer 使用 textarea 和按会话保存的草稿、图片队列；gateway 的 browseWorkspaces 仅为登记工作区浏览宿主目录，不是文件候选接口。现有图片上传使用会话附件 ID 和有界分块，尚无 Web 选择宿主图片的导入入口。

## Goals / Non-Goals

**Goals:** 尽量复用 Pi 的终端体验，以薄适配补齐工作区规则；Web 保留原生文本编辑能力，两端引用语义一致；查询不会阻塞回答或污染其他会话草稿。

**Non-Goals:** 不实现编辑器文件树、全文索引、文件编辑、正文预注入、目录递归附件、跨工作区候选或新的工具权限沙箱；不升级 Pi，不复制其编辑器实现，不自动下载工具。

## Decisions

### 1. 引用为文本，图片为显式附件

普通引用采用 @path 或 @"path with spaces"；选中目录保留 /，可以继续补全，也可关闭候选后直接发送。没有独立普通文件附件对象或历史迁移。文本引用保持可编辑、可复制，模型通过已有工具获取内容。

图片候选选中后沿用现有附件处理。TUI 修正基于工作区解析相对路径以及引号匹配，异步结果绑定会话和草稿版本。Web 增加会话级宿主图片导入与暂存图片分块预览能力：从该会话工作区解析相对路径，重新验证真实目标、格式和大小，放入已有附件暂存池，返回附件 ID 和描述；预览通过有界分块读取，禁止在候选响应中嵌入 base64。释放、提交、失败重试继续沿用附件生命周期。无会话工作区可搜索，选择图片时通过现有新建流程建立对应工作区会话后导入。

相比自动读全文，这保留了用户对上下文大小的控制；图片例外与现有产品约定一致。

### 2. 工作区范围与发现策略

共享浏览器安全的引用解析/格式化规则；共享宿主侧的根目录解析、路径包含关系、真实路径校验和 fd/fdfind 检测，不把 pi-tui 引入 core 或 Web 浏览器包。

空查询给有限候选，有斜杠时按父目录缩小范围，否则模糊搜索。支持普通隐藏项，遵守 fd 的 ignore 规则，显式排除 .git；不强制排除用户主动纳入项目的其他目录。@ 查询不接受绝对路径、~ 或规范化后越界的 ..；手工输入其他普通文字与原有工具行为不受影响。符号链接只有真实目标在根内才可成为候选，断链跳过，提交图片时再次检查。

这是候选范围约束，不宣称 Pi 的 --follow 遍历是文件系统沙箱。Pi 查询可能跟随链接后再由适配层过滤，必须施加超时/取消；Web 查询不主动递归跟随目录链接，合法根内链接可显式定位。两端候选顺序不要求逐项相同，类型和范围规则一致。

### 3. TUI 保留原生提供器

在启动时检测 PATH 中的 fd/fdfind，将可执行文件路径作为 CombinedAutocompleteProvider 第三个参数。用组合式 AutocompleteProvider 适配器委托原生 getSuggestions/applyCompletion，额外校验 @ 查询和候选、组合超时与取消信号，保留 slash 和非 @ 路径行为。缺少工具显示英语提示，不静默降级为每次按键递归 readdir，也不引用 coding-agent 私有工具下载模块。

Pi 返回候选最多 20 项；达到上限时展示“缩小查询”的提示，不伪称完整目录。复用 Pi 排序、引号、撤销、Tab/Enter，不修改 node_modules。宿主层的 Esc 监听先检查原生补全是否激活，让第一次 Esc 交给 Pi；关闭候选重置双击清空序列，随后停止运行仍有效。

### 4. Web 查询服务与性能边界

新增 workspaceFiles 服务，输入 workspaceRoot（已登记身份）及相对查询，输出 entries（name、path、kind）和 limited 状态。通过 Chord Context 传播取消，客户端另用工作区/会话/查询序号屏蔽晚到响应。服务端使用参数数组执行 fd，禁止 shell 拼接，返回路径按 NUL 分隔解析。只处理元数据，不读取正文。

初始预算：查询最多 2048 字符、候选最多 100 项、子进程输出最多 1 MiB、超时 2 秒；达到任一扫描预算明确 limited 或 timeout。每连接只保留一个活跃查询，全局最多 4 个并发查询，额外请求返回可重试 busy；取消释放槽位并终止子进程。前端约 120ms 防抖。第一版不建持久索引、不启动文件 watcher，避免在大工作区长期占用资源。具体常量可按验收调小，不能移除有界约束。

不复用 browseWorkspaces，因为它允许任意宿主绝对目录且仅列目录；候选必须绑定已登记工作区并包含文件。

### 5. Web 保留 textarea，新增候选面板

使用 Floating UI 定位候选层，采用输入框上方起始边锚定、视口翻转/偏移/限高；相比精确跟随字符光标，这种定位更适合多行输入和移动键盘，也无需复制 textarea 字体测量布局。桌面默认显示约 6–8 行，触屏使用足够大的命中区，不新增全屏目录弹窗。

使用 WAI-ARIA 可编辑候选模式的焦点与选中项管理原则；针对多行 textarea 校验合法 ARIA 属性，不直接照搬单行 combobox 示例。上下选择、Enter/Tab 接受、Esc 关闭，Shift+Tab 保留浏览器反向焦点导航。候选打开时 Enter 不发送，中文 composing 时不截获确认。只有词边界的 @ 触发，邮箱不触发；只替换当前 token，保持 selection 和文本后缀。/ 与 @ 共用候选弹层组件，宽度随 textarea 对齐，统一选中样式、快捷键提示和定位，任何时刻只显示一种。

选择项显示类型、名称、父路径；长路径可查看完整值，使用聊天区蓝粉白 design tokens。加载、空态、失败、缺少 fd 和 limited 分别反馈。关闭、失焦或工作区切换取消查询，过期结果不得重开面板。

参考： https://floating-ui.com/docs/react 、https://www.w3.org/WAI/ARIA/apg/patterns/combobox/ 。浏览器目录选择器面向浏览器设备，不能替代宿主网关查询。

## Risks / Trade-offs

- [外部 fd 依赖] → 提供安装提示并保留手动路径和普通聊天；不自动联网下载。
- [Pi 私有细节变化] → 只依赖已安装 1.1.0 公共接口，适配器以真实提供器做行为测试，不复制私有算法。
- [忽略和有限扫描导致未命中] → 明确有限候选与缩小范围提示；不承诺完整遍历或全局最优排名。
- [文件变化与符号链接竞争] → 候选仅为提示，图片导入重新校验，实际文件工具继续返回真实错误；不声称安全沙箱。
- [候选按键与停止/清空冲突] → 测试 idle/busy、补全开关、Esc 连按及输入法状态组合。
- [图片暂存资源泄漏] → 导入使用现有会话附件所有权和清理策略，关闭/取消/迟到结果均释放资源。

## Migration Plan

新增网关方法和前端能力随同一版本发布，无会话数据库迁移、历史清理或凭据变更。实现依次为共享规则与网关、TUI、Web、集成验证。回滚该变更恢复原输入框和补全接入，不影响已保存的普通引用文本或图片消息。仅依赖变化时更新 bun.lock；测试快照和临时文件在验收后删除，不归档。

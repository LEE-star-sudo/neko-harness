# Proposal

## Why

用户需要在对话中快速定位并引用当前工作区的文件和目录。TUI 已接入 Pi 补全组件但未提供 fd 路径，导致 @ 候选为空；Web 尚无对应入口，手工输入长路径容易出错。

## What Changes

- TUI 优先复用已安装 Pi 1.1.0 的补全提供器、编辑器和键盘行为，检测 fd/fdfind，补齐缺失依赖提示及候选关闭优先级。
- Web 保留 textarea，加入 @ 文件候选面板、路径定位与模糊搜索，支持键盘、触屏、中文输入法及蓝粉白聊天区风格。
- 新增网关工作区文件查询接口，与添加工作区的宿主目录浏览分离；只返回当前工作区内的路径元数据，有界、可取消、不串会话。
- 双端统一路径引用语义：普通文件和目录只插入引用，不自动加载正文或递归展开目录；模型按需使用现有工具。图片沿用附件能力。
- 不升级 Pi、不引入完整 coding-agent、不新增富文本编辑器、不自动下载 fd，不改变工具的宿主访问权限或会话存储格式。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workspace-management`: 工作区文件候选范围、忽略规则、资源边界和路径引用语义。
- `session-gateway`: 提供绑定工作区的文件候选查询与取消、错误反馈。
- `terminal-ui`: Pi 原生 @ 补全接入、依赖提示、键盘优先级及图片兼容。
- `web-ui`: Web @ 候选交互、响应式呈现和异步草稿隔离。

## Impact

涉及 core 的共享路径规则、gateway 的文件查询服务和契约、TUI 补全接入与编辑器、Web composer 和客户端契约。Web 拟增加 Floating UI 定位依赖，由 Bun 精确锁定；宿主需要 fd 或 fdfind。测试覆盖路径边界、取消、引用文本、现有图片流程和两端输入交互，测试截图不归档。

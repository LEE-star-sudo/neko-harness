# Spec Delta

## ADDED Requirements

### Requirement: Web 忙时发送

Web 输入框 SHALL 在会话运行中保持可编辑并允许发送，发送的消息一律排队，输入区内 MUST NOT 提供预选投递方式的开关。按钮与占位文案 SHALL 说明消息将在回答结束后排队处理。发送后沿用草稿保留、requestId 幂等与失败保留规则；`/compact` 命令 MUST 仍先于普通消息解析。

#### Scenario: 运行中发送

- **WHEN** 会话正在回答，用户输入文字并点击发送
- **THEN** 消息被受理并出现在排队条中，草稿清空，输入框保持可用，当前回答不中断，输入区没有引导开关

#### Scenario: 受理失败

- **WHEN** 电脑拒绝该次忙时提交
- **THEN** 保留草稿与附件并显示原因，不显示已排队，同一草稿重试沿用原 requestId

#### Scenario: 空闲时发送

- **WHEN** 会话空闲
- **THEN** 发送行为与现有一致，按钮不显示排队文案

### Requirement: Web 排队条的引导与撤回

Web SHALL 在输入区上方显示当前会话排队输入条，每项含投递方式标识、文字预览与图片数量；仍为排队的项提供「引导」与「撤回」，已是引导的项只提供「撤回」，无排队项时不占位。引导后该项标识变为引导并留在条中直到进入 transcript。撤回 SHALL 把文字取回草稿（草稿为空时覆盖，否则追加到新行），带图片的项仅取回文字并提示图片未恢复；操作结果为已放入时提示已发送并不改草稿。排队条在 375、768、1440、1920 像素宽度下无横向溢出，可键盘操作并有可访问名称。「停止」保持清空全部排队并中止运行。

#### Scenario: 引导一条排队消息

- **WHEN** 用户点击某排队项的「引导」
- **THEN** 该项标识变为引导且不再提供「引导」，草稿与其他排队项不变，当前运行不中断

#### Scenario: 撤回并取回文字

- **WHEN** 用户点击某排队项的撤回，草稿为空
- **THEN** 该项消失，其完整原文回到输入框可再次编辑发送，其余排队项不变

#### Scenario: 撤回时草稿非空

- **WHEN** 用户已在输入框键入新内容并撤回某项
- **THEN** 被撤回文字追加到草稿新行，不覆盖用户的新内容

#### Scenario: 已被放入

- **WHEN** 用户点击引导或撤回时该消息刚进入 transcript
- **THEN** 显示该消息已发送的提示，草稿不变，transcript 中保留该消息

#### Scenario: 旧网关

- **WHEN** Web 连接不提供排队列表的旧网关
- **THEN** 不显示排队条、引导与撤回入口，忙时仍可发送

#### Scenario: 切换会话

- **WHEN** 用户在有排队项的会话与其他会话之间切换
- **THEN** 排队条只显示当前会话的项，不串会话，不影响各会话草稿

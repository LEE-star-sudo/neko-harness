# Spec Delta

## ADDED Requirements

### Requirement: 排队输入观察与撤回服务

网关 SHALL 在会话视图中提供该会话的用户排队输入列表（提交标识、投递方式、有界文字预览、图片数量、技能标记），并提供按提交标识把单条排队输入改为引导、或撤回它的接口。预览 MUST 有长度上限，列表 MUST NOT 含图片数据；两个操作 MUST 校验提交属于该会话，并返回明确结果（已引导、已撤回、已放入、已结束或未知）。引导改变投递方式后提交标识可能变化，前端 SHALL 以视图中的列表为准。列表变化 SHALL 同步到所有已连接前端。

#### Scenario: 多端同步

- **WHEN** Web 与 TUI 同时查看同一会话，一端提交排队消息，另一端把它改为引导或撤回
- **THEN** 两端最终都显示相同的结果，transcript 中不出现重复输入，且只发生一次操作

#### Scenario: 超长输入预览

- **WHEN** 用户排队一条数万字的消息
- **THEN** 视图广播中只含有界预览，完整内容在放入 transcript 后按既有方式读取

#### Scenario: 重连

- **WHEN** 前端断线后重新连接
- **THEN** 恢复真实的排队列表，不重复提交也不自动撤回任何项

### Requirement: 排队接口的向后兼容

排队列表、引导与撤回接口 SHALL 作为可选扩展加入，不提升应用协议版本，不得使既有客户端失去原有功能。旧客户端连接新网关时 MUST 忽略新增字段而正常工作；新客户端连接不含该能力的旧网关时 SHALL 隐藏排队列表、引导与撤回入口，仍允许发送，MUST NOT 因缺少字段而报错或判定应用协议不兼容。

#### Scenario: 新界面连接旧网关

- **WHEN** 新 TUI/Web 连接尚不支持排队列表的旧网关
- **THEN** 会话照常使用，忙时仍可发送，排队列表与撤回入口不显示，不触发协议不兼容的阻断

#### Scenario: 旧界面连接新网关

- **WHEN** 旧版客户端连接新网关并在运行中发送消息
- **THEN** 发送与停止照常工作，客户端忽略排队字段，不报错

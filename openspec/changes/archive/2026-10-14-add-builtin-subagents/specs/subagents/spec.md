## Purpose

为主 agent 提供内置子 agent 的前台任务委派能力，在独立对话上下文中完成调查、规划或实现，并让用户跨界面观察、停止和恢复任务，保持任务归属及最终结果一致。

## ADDED Requirements

### Requirement: 内置角色与工具边界
系统 SHALL 提供 explore、plan、coder 三种内置角色。explore 与 plan SHALL 具有文件发现、内容搜索、读取以及已配置的网络调研能力，不具有文件写入、编辑或任意 shell 执行能力；coder SHALL 可使用现有编码工具。所有子 agent MUST 无法再次委派；未知角色 MUST 被拒绝。

#### Scenario: 未知路径调查
- **WHEN** 主 agent 向 explore 提交仅包含调查目标而没有具体文件路径的任务
- **THEN** 子 agent 能发现文件、搜索内容、读取证据并交付结论，不能修改工作区

#### Scenario: 实现和角色限制
- **WHEN** coder 执行明确的实现任务，或只读角色尝试写入、执行 shell、嵌套委派
- **THEN** coder 可修改并验证；受限调用在执行前被拒绝，不仅从模型工具列表隐藏

### Requirement: 前台委派与上下文隔离
系统 SHALL 允许主 agent 提交角色、任务正文和简短标题进行前台委派，子 agent 仅接收显式任务材料及自身系统资源，不复制主会话历史。子 agent SHALL 继承派发时的模型、思考强度和工作目录。主 agent SHALL 等待本轮委派结算，再收到最终报告或明确失败；中间日志 MUST NOT 自动注入主模型上下文。

#### Scenario: 并行调查
- **WHEN** 主 agent 同轮委派多个独立调查
- **THEN** 子任务可并行运行且上下文隔离，主 agent 在本轮工具结算后汇总各自结果

#### Scenario: 输入材料不足
- **WHEN** 子 agent 无法从明确传入的材料完成任务
- **THEN** 返回缺失信息或限制给主 agent，不伪造已访问主会话历史或已完成任务

### Requirement: 委派取消与恢复
委派及子会话 SHALL 持久关联，恢复同一次调用 MUST 复用原子会话与已受理输入。停止主会话 SHALL 级联停止本轮全部子任务；单独停止子任务 SHALL 不停止兄弟任务，主 agent 获得取消结果。浏览或断开前端 MUST NOT 取消执行。取消 MUST NOT 被宣称回滚已发生的文件修改。

#### Scenario: 重启时任务未完成
- **WHEN** gateway 在派发后、结果回传前重启
- **THEN** 沿原生任务恢复语义继续或报告中断，不重复创建子会话、重复提交任务或无条件重放有副作用的工具

#### Scenario: 单独停止和全局停止
- **WHEN** 用户停止一个子任务或停止正在等待的主会话
- **THEN** 前者仅停止目标并保留兄弟任务，后者停止所属子任务并保留可查看的已产生记录

### Requirement: 持久委派记录与容量
系统 SHALL 保存委派所属主会话、调用身份、子会话、角色、标题及最终结果状态，区分排队、运行、完成、失败和停止。完成状态 SHALL 以实际运行结算为准，不能以一次内部工具失败判断整个子 agent 失败。并发 SHALL 有界；首版每主会话最多同时运行三个子 agent，同一规范化工作区最多运行一个 coder，多余任务可取消地等待。

#### Scenario: 完成后的历史
- **WHEN** 子任务结束并从活跃任务图移除，随后客户端重连或 gateway 重启
- **THEN** 委派记录及最终状态仍可查看，不变成未知或永久运行

#### Scenario: 队列取消
- **WHEN** 达到并发上限后新任务等待，用户停止主会话
- **THEN** 排队任务一并停止，之后不再启动或占用运行配额

#### Scenario: 工具错误后恢复
- **WHEN** 子 agent 某次命令失败但继续修复并最终正常交付
- **THEN** 内部流程保留失败工具卡，委派状态按最终结算显示完成

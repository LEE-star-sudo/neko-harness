# Proposal

## Why

TUI 启动时选择全局最早会话，启动目录、工具目录与状态栏目录可能不一致。底部状态区域可被布局压缩，选择弹层会被直接裁剪，且产品文案中英混杂，需要统一工作区语义和终端交互设计。

## What Changes

- 以 `--cwd` 或启动目录定义工作区，不自动扩大到 Git 根目录；会话持久绑定工作区，新建与 fork 保持目录一致。
- TUI 仅展示当前工作区会话，恢复最近使用会话；补全与状态栏使用同一工作区。
- **BREAKING**：不兼容旧会话数据，不做归属推断或迁移。用户已授权并于 2026-10-11 清空本机测试会话存储；应用启动不得自动删除存储。
- 重新分配聊天、输入和常驻状态栏空间，按窗口尺寸精简信息；统一 TUI 产品文案为英语、主题语义和真实快捷键行为。
- 统一模型与会话选择面板，提供可见的选中项、动态高度、滚动、搜索、加载与错误反馈，恢复草稿与焦点。
- 工作区为默认工作上下文，不是访问沙箱；保留工具显式访问其他目录的能力。

## Capabilities

### New Capabilities

无；复用现有运行时、网关和终端能力边界。

### Modified Capabilities

- `agent-runtime`：会话工作区持久化、默认执行目录和 fork 继承。
- `session-gateway`：目录暴露工作区与最近使用信息，投影真实会话目录，支持共享网关多工作区。
- `terminal-ui`：工作区会话管理、常驻响应式状态栏、英语文案与统一选择面板。

## Impact

涉及 core runtime/projection、gateway contract/server-services/session-host、TUI 启动与布局组件及相关测试和文档。Web 仅适配共享契约与正确目录语义，保留其全局会话浏览能力；不重设计 Web。保留 Bun 与 Pi 1.1.0 精确依赖，不新增沙箱、不修改上游或 reference，不在此规划阶段实施代码。

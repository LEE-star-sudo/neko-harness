# Design

## Context

动机见 proposal.md。当前 runtime 使用可选 agent.cwd 和进程目录回退；gateway 目录条目仅含 id，投影目录取网关级参数。TUI 启动选择最小 id，footer 与外层 dock 都允许收缩；PickerOverlay 固定十项，上游 maxHeight 通过截断渲染行实现。状态栏在斜杠输入之外消失的精确触发仍需在实施时用固定尺寸帧与 PTY 复现，不能把布局风险直接当作唯一根因。

现有 core/gateway 测试覆盖恢复、目录与 attach；TUI 暂无专用测试目录。保留现有 Pi 1.1.0、Bun 和上下游薄封装。

## Goals / Non-Goals

**Goals:** 单个共享网关正确托管多个工作区；持久会话目录为工具、投影和补全的共同依据；布局有明确高度预算与焦点生命周期。

**Non-Goals:** 文件系统权限隔离、bash 沙箱、跨目录授权流程、旧数据迁移、Web 视觉改版、上游升级。

## Decisions

### D1. 工作区身份与会话执行目录

TUI 启动前解析 `--cwd ?? process.cwd()`，校验目录并通过 realpath 规范化；符号链接指向同一目录视为同一工作区，子目录保持独立，不搜索 Git 根。将规范化路径用于配置查找、会话创建及补全。gateway/core 创建入口同样校验，防止其他前端产生不一致记录。恢复已有会话不重新绑定路径，目录失效明确报错。

会话创建时始终写入 agent.cwd，作为 workspaceRoot 的持久事实来源，业务元数据仅保存最近使用信息，避免两份目录真值。root 初始化也使用已解析默认目录；独立新建显式提供完整目录；有历史 fork 继承 agent.cwd，空会话 fork 的新建分支显式复制目录、模型与 thinking。投影读取会话 agent.cwd，不再接收网关级目录覆盖。

备选：每目录启动独立 gateway/数据库。拒绝，因为破坏现有共享网关及 Web attach 体验。仅在 UI 中显示 cwd 也无法解决实际执行目录错误。

### D2. 最近使用与目录协议

在宿主会话文档保存 lastUsedAt；创建、成功激活（首次 attach/切换）和接受用户提交时更新，不在每个输出事件更新。重复 attach 保持幂等，不持续提升排序。以时间降序、id 数值降序处理并列，gateway 对宿主事件统一更新并推送。目录摘要增加 workspaceRoot/lastUsedAt；ChatView.cwd 使用会话事实来源。

目录服务仍广播全局目录，TUI 对规范化工作区做精确相等筛选，启动恢复最近非归档项；切换、归档后的回退、新建都使用同一筛选规则。Web 保持全局目录与现有 UI，省略创建目录时由 gateway 提供固定默认目录，fork 继承源会话。工作区不是授权边界，无需把目录服务重构为隔离租户服务。

### D3. 常驻布局与信息优先级

抽取可独立渲染测试的根布局与 footer。聊天 ScrollView 吸收剩余空间，底部显式保留输入和状态栏高度，不允许 footer 被压缩为零。限制多行编辑器高度，补全和 notice 有独立预算；忙碌状态并入 footer，避免重复 loader 占行。短暂通知不得长期挤占底部。

正常布局：

```text
+------------------------------------------------------------------+
| Conversation                                                     |
|                                                                  |
+------------------------------------------------------------------+
| > Ask a question or describe a task                               |
+------------------------------------------------------------------+
| neko-harness | deepseek-flash | Think: high | Ready                |
| In: 12k Out: 2k $0.012 | Enter Send  Ctrl+S Sessions  / Commands   |
+------------------------------------------------------------------+
```

按可见终端列宽计算，不按字符串长度。优先级：工作区/状态 > 模型 > thinking > 用量 > 附加提示；路径可缩写，完整路径在会话面板详情显示。40x10 为可用下限，小于此尺寸进入可恢复的尺寸提示视图；60x16 保留精简 footer。详细用量放在会话详情，避免新增一组无必要命令。

备选：仅强制重绘 footer。拒绝作为完整方案，因为无法保证布局高度和小窗口信息取舍。

### D4. 统一选择面板与状态机

模型与会话选择使用同一面板控制器，以聊天区域为边界；小窗口面板占满该区域，底部输入/状态仍可见。分配标题、搜索、帮助和可选详情高度后，将剩余行数交给列表滚动，不依赖上游 maxHeight 裁剪。列表项使用短标签，当前项标记 Current，选择指示符独立于颜色；长 provider/modelId 与路径在详情区按宽度折行且有高度上限。

状态为 closed/loading/ready/error，搜索无结果在 ready 中显示 No results。打开即设置唯一面板状态；请求带 generation token，关闭或新请求使旧结果失效。面板内部处理导航、输入、Enter、Esc；全局快捷键不得绕过面板焦点。取消和成功选择恢复草稿、光标和编辑器焦点。选择应用期间防重复提交，错误保留可恢复界面。斜杠补全保留编辑器内的轻量交互，不与选择面板叠加。

备选：继续使用全屏居中遮罩。拒绝，因为终端高度有限，遮挡底部上下文且难以与补全一致共存。

### D5. 英语文案与主题

集中管理 TUI 自有 labels、notice 和键位提示，统一 sentence case。对用户可见的 gateway 错误增加英语上下文，原始工具/provider 诊断内容原样保留；不翻译聊天内容。保留明暗自动检测，增加一致的 panel/border/selection/muted 语义槽位。状态字和选择标记始终存在，不只靠颜色传达。Ctrl+C 忙碌时 Stop、空闲时 Exit，与现有行为一致；所有提示由实际可用动作生成。

## Risks / Trade-offs

- [全局目录仍包含其他工作区] → 明确为上下文组织而非安全隔离，TUI 筛选，Web 保持全局浏览。
- [目录改名或删除] → 原归属保持，操作报错；本轮不做自动目录迁移。
- [终端 ANSI、宽字符和主题差异] → 帧级可见宽度断言与真实 PTY 验证结合，覆盖中文内容、长路径、resize。
- [异步面板和会话切换竞争] → 请求代次、操作串行化与焦点恢复测试。
- [最近使用更新引入额外提交] → 仅宿主激活/输入更新，不随流式事件提交；检查重复 attach 幂等与广播。

## Migration Plan

1. 已于 2026-10-11 按用户授权停止当前 gateway，硬删除 `~/.neko/neko.sqlite`、`-wal`、`-shm`；只保留 gateway 身份文件，未备份测试历史。
2. 实施使用全新测试存储，完成 core/gateway/TUI 与 Web 契约适配后启动新版本。缺少工作区的旧存储不推断、不迁移；检测到时给出明确不支持提示且不自动删除。
3. 发布前通过构建、检查、回归测试及 PTY 验收。文档说明工作区语义与非沙箱边界。
4. 回滚代码不恢复已硬删除测试历史；不承诺新旧会话存储互操作。不得将此次一次性授权做成启动清理逻辑，也不自动清理后续新数据。

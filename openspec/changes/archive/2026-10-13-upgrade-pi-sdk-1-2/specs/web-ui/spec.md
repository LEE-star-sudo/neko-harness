# Spec Delta

## MODIFIED Requirements

### Requirement: 断线重连

系统 SHALL 在 WebSocket 断开后自动重连；重连后从当前视图状态恢复，不重放历史事件。重连 SHALL 保留当前工作区并优先恢复原会话；原会话已归档时仅回退到同工作区最近使用会话，无可用会话则显示该工作区空态。连接建立与实际状态就绪 MUST 分开：目录、工作区和凭据首个快照到达后才能开放管理操作，当前会话视图到达后才能开放会话操作；失效连接的迟到响应 MUST 不覆盖新连接。

#### Scenario: 网络抖动恢复

- **WHEN** WebSocket 断开 10 秒后恢复
- **THEN** 界面自动重连并展示会话最新状态，期间到达的回答完整可见，工作区不变

#### Scenario: 原会话不再可用

- **WHEN** 断线期间原会话被另一前端归档
- **THEN** 重连后选择同工作区最近使用会话或显示空态，不连接其他工作区会话

#### Scenario: 连接已建立而快照未到达

- **WHEN** 初次连接或重连的服务已绑定，但首个订阅快照仍在传输中
- **THEN** 相应管理或会话操作保持未就绪，不将旧视图或空状态当成新快照；失败时保留草稿并提供错误反馈

### Requirement: 会话模型与思考强度设置

Web SHALL 在聊天区同一配置面板内提供模型和思考强度选择，选项取自与 TUI 相同的 Pi 1.2.0 能力列表，一次确认提交当前会话配置。面板 SHALL 显示当前值、切换模型后的有效强度及“从下一次请求生效”说明；输入卡片工具行展示服务端确认值。设置页的用户级凭据与会话级模型配置 MUST 清楚区分。

#### Scenario: 切换和取消

- **WHEN** 用户从 Flash low 选择 Pro
- **THEN** 草稿强度按 Pi 调整为 high 并显示，确认后模型和强度一并生效；取消不改变会话

#### Scenario: 双端一致

- **WHEN** Pi 1.2.0 下选择 Flash 或 Pro，或 TUI 修改当前会话
- **THEN** Flash 提供 off/low/high/max、Pro 提供 off/high/max；Web 同步实际生效配置，不提供其他档位

#### Scenario: 切换会话与请求失败

- **WHEN** 配置面板打开期间切换会话，或提交失败、返回过期响应
- **THEN** 不向新会话误提交旧草稿，不让旧响应覆盖新会话；失败保持实际生效值并提示重试

#### Scenario: 面板访问

- **WHEN** 用户通过键盘或触屏从输入卡片工具行打开模型面板
- **THEN** 可完成选择和确认，Escape 可取消并恢复焦点，面板在小屏中不越界或遮挡无法访问的操作

### Requirement: 图片预览与响应式访问

Web SHALL 在历史中显示图片缩略图，按需加载大图并提供关闭入口；统一 read 工具的图片结果 SHALL 使用相同的预览能力，展示路径名称、格式、实际保存尺寸和原生处理诊断。附件、命令菜单和预览 SHALL 遵循全站统一的蓝粉白主题，支持键盘和触屏，且在 1440、1024、768、375、1920、2560 像素宽度下可访问、不横向溢出。预览关闭后恢复焦点，移除和关闭操作有明确可访问名称。

#### Scenario: 大图与菜单

- **WHEN** 用户打开大图、滚动长附件列表或在小屏展开命令菜单
- **THEN** 操作不被遮挡，模态预览约束焦点并支持 Escape，菜单取消恢复编辑且不误发消息

#### Scenario: read 图片结果与恢复

- **WHEN** read 返回图片，随后源文件消失或浏览器重连
- **THEN** 从持久结果按需恢复预览及元数据，订阅状态不重复携带 base64，不依赖原宿主文件仍存在

#### Scenario: 图片读取失败或能力占位符

- **WHEN** read 无法处理图片，或当前非视觉模型只收到占位符
- **THEN** 工具卡可辨识地显示失败或能力诊断，不能将占位符表现为模型已看见图片

### Requirement: Web 技能调用消息展示

Web SHALL 依据服务端投影的结构化技能元数据将成功展开的技能调用渲染为工具卡风格的折叠卡片：技能图标、`skill:<name>` 名称与截断来源路径，默认折叠，点击展开查看正文（等宽、限高滚动）。参数 SHALL 在卡片外以普通用户文本显示。无技能元数据的输入 MUST 原样渲染，不从 XML 文本反向识别，不丢失内容。卡片 SHALL 遵循全站统一的蓝粉白 design tokens。

#### Scenario: 折叠卡片

- **WHEN** 用户通过 `/skill:pdf 总结它` 提交且技能命中展开
- **THEN** 该用户消息显示为折叠的技能卡片（图标 + `skill:pdf` + 来源路径），正文不铺开

#### Scenario: 展开正文

- **WHEN** 用户点击技能卡片
- **THEN** 卡片展开显示技能正文，再次点击折叠

#### Scenario: 参数仍可见

- **WHEN** 技能调用带有参数
- **THEN** 参数文本在卡片外以普通用户消息样式显示

#### Scenario: 解析失败回退

- **WHEN** 用户消息以 `<skill` 开头但没有成功展开的结构化技能元数据（如手工输入、未命中透传）
- **THEN** 消息按原样纯文本渲染，内容完整可见，即使 XML 外观符合技能块也不解析为调用

#### Scenario: 元数据恢复

- **WHEN** 浏览器重连或打开分叉后的 Pi 1.2.0 会话，技能正文及参数含有 XML 标记
- **THEN** 从持久展示数据恢复卡片、正文和参数，边界不受 XML 内容影响

## ADDED Requirements

### Requirement: Web 文件发现状态反馈

Web 的 @ 候选面板 SHALL 区分加载、完整无匹配、候选过多、枚举不完整和文件发现失败。正常安装后无需用户安装 fd/fdfind；辅助组件缺失或不可用 SHALL 返回可理解且可重试的错误，不指导安装 fd，也不伪装为空结果。反馈 SHALL 保留草稿，不阻止关闭候选后发送普通消息；取消或工作区切换后的旧响应 MUST NOT 重开面板。

#### Scenario: 无 fd 的安装

- **WHEN** 支持平台正常安装 neko，gateway 的 PATH 没有 fd/fdfind，用户触发 @ 补全
- **THEN** 正常展示候选，不显示安装命令；浏览器与宿主平台不同不影响该行为

#### Scenario: 不完整而没有匹配

- **WHEN** 后端目录枚举截断，返回零个匹配候选
- **THEN** 面板明确提示结果不完整并引导指定子目录，不显示普通“没有匹配”；指定子目录后可重新查询

#### Scenario: 组件故障与恢复

- **WHEN** 随包文件发现组件缺失、不可执行或启动失败，随后恢复并再次查询
- **THEN** 初次显示文件发现不可用与重试反馈，保留草稿；再次查询可恢复候选，不要求安装 fd

#### Scenario: 查询结束与取消

- **WHEN** 搜索超时、被取消，或用户关闭候选/切换工作区后旧请求结束
- **THEN** 超时可辨识且可重试，取消不显示组件安装错误；旧反馈不恢复面板或覆盖新工作区结果，普通消息仍可发送

## REMOVED Requirements

### Requirement: Web 文件补全依赖安装引导

**Reason**: 文件发现由随包本地组件提供，不再依赖宿主 fd/fdfind 或用户手动安装。

**Migration**: 删除平台安装命令、fd 探测与专用错误映射，采用文件发现状态反馈；故障通过可重试错误处理，保持草稿及普通消息可用。不保留 fd 后端回退。

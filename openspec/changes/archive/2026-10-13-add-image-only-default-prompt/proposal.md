# Proposal

## Why

用户只发送图片时，当前模型收到图片但没有明确任务文字，只能依赖历史和通用编程助手角色猜测意图，回应容易不稳定。需要为这种输入提供可追溯、跨前端一致的默认用户提示，而不修改系统提示词。

## What Changes

- 在 core 对包含一张或多张图片、且所有文字块去除空白后为空的新输入，补入一次默认用户提示。
- 提示优先结合当前对话；没有明确任务时说明关键信息与值得关注的问题，意图不明时提出具体问题，不猜测看不清的细节，也不把图片本身当作执行修改的授权。
- 默认提示作为普通用户文字块与图片原子持久化，同时记录来源标记与版本；重试、排队恢复和 fork 使用当时保存的正文。
- 通过会话投影向 TUI/Web 提供默认提示元数据；默认不把正文显示成用户手写内容，提供可查看、可收起的提示入口。
- 保持用户已有文字、旧图片历史、图片验证、图片顺序与首问摘要/命名占位语义。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-runtime`: 纯图片输入的默认用户提示、来源标记、持久化与恢复行为。
- `terminal-ui`: 默认图片提示的来源标记及正文查看交互。
- `web-ui`: 默认图片提示的折叠展示、可访问查看入口与恢复行为。

## Impact

- core 的图片输入准备、runtime 准入、NekoInput 元数据与 ChatItem 投影。
- gateway 的用户条目状态 schema，新增可选字段；不新增 RPC 或客户端提交参数。
- TUI 用户消息组件与转录交互、Web UserRow，以及相关图片、投影、边界和 UI 测试。
- README 的纯图片输入说明。无依赖升级、系统提示词更改或历史数据回填；不新增设置项或前端本地补词。

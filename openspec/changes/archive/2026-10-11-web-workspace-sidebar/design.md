# Design

## Context

动机见 proposal.md。core 已通过 agent.cwd 保存规范化工作区，并使用应用文档保存归档和最近活动。gateway 已返回 workspaceRoot/lastUsedAt，但 Web 的 contract 镜像仍只有 id；GatewayConnection 首连选择全局首项，createSession 传空参数，bootstrap 归档后也从全局取下一项。

Web 静态服务与 gateway 是两个进程，复用已有 gateway 时其默认目录不等于 Web 启动目录。现有 `/api/info` 只提供连接信息。会话侧栏的桌面样式强制常显，归档按钮仅 hover 可见并依赖三秒内二次点击；全局 CSS 的粉蓝渐变和按钮样式不能直接用于新的中性导航。

现有 `web-ui` 规格要求全界面二次元主题，本次通过完整 MODIFIED 块明确分区，同时保留模型输出消毒场景。规格中的旧“网关进程静态托管”描述与当前独立 Web 宿主不同，但本次不改变部署形态、不顺带重写该无关需求。Pi 1.1.0 与 Bun 工具链保持不变。

## Goals / Non-Goals

**Goals:** 用现有 SQLite 生命周期管理工作区目录，使目录身份、选中工作区和实际 attach 会话保持一致；在现有 React 架构中完成可键盘操作的目录选择及导航。

**Non-Goals:** 系统原生目录窗口、浏览器文件上传、独立文件管理器、工作区删除/重命名、会话迁移、会话标题生成、账户系统、新的权限沙箱及聊天区视觉重做。

## Decisions

### D1. 独立记录与会话归属

在现有 Harness 存储中增加应用文档 `app.neko.workspaces`，由稳定 root 会话承载全局记录，业务意义与 root 的显示/归档状态解耦，分叉不复制目录。记录使用规范化真实绝对路径作为键并保存 createdAt；显示名从 basename 派生，完整路径用于消歧。通过 Harness 事务去重并避免并发添加丢失更新，不另建 JSON 文件或第二个数据库连接。

启动时分页扫描已有全部会话（含已归档会话），将保存的 cwd 幂等登记。接入已有路径时不重新 realpath，以免目录消失或符号链接变化导致身份重绑定；显式添加必须重新 realpath 并验证目录可读取、可进入。root、新建和 fork 的工作区自动登记，归档不移除工作区。新建会话前先登记已验证工作区；若随后创建失败，保留空工作区是合法状态。

备选“按活跃会话临时分组”无法保存空工作区；浏览器 localStorage 不能满足跨客户端与重启一致性，因此不作为工作区事实源。

### D2. 网关协议与宿主目录浏览

增加服务器级 `neko.workspaces` 服务，提供工作区目录复制状态、`add({ path })` 与 `browse({ path, query, showHidden, cursor })`。现有会话目录继续全局广播，Web 进行精确路径筛选；浏览器镜像补齐会话 metadata，并对新旧契约做一致性测试。

browse 只读单层目录，不返回文件内容；返回真实路径、父目录、子目录名称和路径、下一页 cursor。默认每页 100 项，目录名采用确定性排序；过滤在分页前完成，cursor 与路径/过滤条件绑定，参数变化后重置。符号链接目录可选，进入后返回真实路径；损坏或不可进入项明确禁用或报告错误，不伪装为空目录。默认不显示点号隐藏项，根路径的 parent 为 null。

面板打开才发起浏览请求，不递归预扫宿主文件树；列出阶段允许只读查看，确认添加时再次验证，覆盖浏览后目录被删除的情况。该能力沿用现有本地可信网关访问边界，默认监听地址不改变，不新增独立公开文件浏览 HTTP 服务。

备选浏览器 File System Access 句柄不能直接充当工具所需的宿主绝对路径；系统原生窗口依赖桌面会话且远程访问体验不一致，均不采用。

### D3. 初始工作区与操作状态机

Web 服务启动时规范化 `options.gateway.cwd ?? process.cwd()`，即使复用已有网关也保留此值；`/api/info` 新增 `workspaceRoot`。浏览器完成服务绑定后确保该工作区登记，等待目录初始快照，再选择其中最近使用会话。刷新回到该 Web 实例的启动工作区；同一页面生命周期的重连保留用户当前选择，不把刷新与重连混为一类。不新增 localStorage 的跨启动恢复优先级。

store 显式区分 workspaceRoot、currentSessionId、连接状态、导航操作状态与 view。网关服务就绪和会话就绪分开：空工作区允许新建，未 attach 时禁止发送。进入工作区按 lastUsedAt 降序、会话数值 id 降序选中，排序与 TUI 一致；没有会话不自动创建。

所有 attach/create/archive/detach 通过一个有序操作入口执行，切换期间禁用重复操作和发送；异步 view、目录响应与重连使用 generation 检查，旧结果不得覆盖新状态。新建始终传当前路径；操作成功后才发布可交互的选中会话。失败恢复一致状态并给出重试入口，不能只变高亮而实际仍指向旧会话。

当前会话被本页或其他前端归档时，同工作区回退或清空 attach；仅目录活动更新时间变化不触发自动切换。另一工作区的新会话广播不抢焦点。已有工作区目录失效时仍允许读历史，创建及工具执行按既有 core 语义报错。

### D4. 目录选择面板

工作区切换器末尾固定“添加工作区”。桌面使用居中、最大宽度约 640px 的模态面板；移动端使用保留安全边距的全屏面板。面板默认当前工作区；没有当前项时使用 Web 启动目录。默认位置失效时显示错误并允许修改路径，不静默跳目录。

顶部为可点击面包屑与完整路径输入，下方名称过滤和隐藏目录开关；中间列表只显示目录并支持上一层、键盘导航和加载更多；底部固定待选完整路径、“取消”“选择文件夹”。进入目录与确认当前目录是不同操作，避免双击即添加。对话框名称、加载状态、错误及选中项具有可访问语义。

状态为 browsing/loading/error/adding；确认时冻结选中路径并防止重复添加。浏览可以取消，关闭后过期 browse 不改变页面；add 已提交时等待结果并禁用关闭，避免出现“已取消但实际添加”的误导。添加失败保留路径供重试，成功后关闭并切换，重复路径直接进入已存在工作区。

### D5. 导航结构与视觉语言

借鉴 Notion 的工作区切换和紧凑内容导航，不复制品牌资产。参考：https://www.notion.com/help/navigate-with-the-sidebar 。布局示意（英文仅作结构示意，首版产品文案沿用当前 Web 的中文，文档正文也用中文）：

```text
+------------------------+--------------------------------+
| neko-harness       v   | neko-harness / Session 42      |
| + New session          |                                |
| Search sessions...     |                                |
|                        |             Chat               |
| Sessions               |                                |
|   Session 42       ... |     Existing pink/blue theme   |
|   Session 38       ... |                                |
|                        |                                |
| Settings               |                                |
+------------------------+--------------------------------+
```

桌面侧栏默认约 256px，行高 32px，正文 13–14px，圆角 4–6px。使用局部 `nav-*` tokens：暖灰底、白色弹层、深灰文字、浅灰 hover/selected、克制分隔线；选中态同时使用字重或标记，不能只靠颜色。中性底色采用不透明 surface 覆盖现有 body 渐变，不全局重定义 sakura/tianyi tokens；导航弹层 portal 显式携带导航主题作用域。

新建入口常驻；会话行菜单占位固定，hover/focus-within 时出现，触屏始终可见，避免行宽跳动。图标统一使用轻量 SVG，所有纯图标按钮提供名称和 tooltip。归档菜单打开明确确认，展示目标会话，支持取消与错误反馈，不使用限时二次点击或垃圾桶暗示硬删除。顶部显示工作区/会话上下文、侧栏开关与紧凑连接状态；工作区完整路径可聚焦查看，同名项附父路径。

保留聊天内容、Composer、StatusBar、模型选择及其粉蓝样式。本次不增加暗色主题或全 Web 语言迁移。

### D6. 响应式与焦点

桌面开关真正移除/隐藏侧栏，聊天区随之扩展；移动端默认关闭抽屉，打开后覆盖底层并锁定背景滚动。隐藏导航不可聚焦。会话切换成功后移动端关闭抽屉并恢复合理焦点；桌面维持导航。

模态面板与抽屉具有焦点约束、Escape 关闭、触发控件焦点恢复；菜单通过 portal 定位并在视口边缘调整，避免 overflow 裁剪，支持 Enter/Space、方向键和 Escape。触屏目标采用至少 44px 的可点击区域，桌面紧凑视觉尺寸不减少触屏可用面积。遵循 reduced-motion，验证键盘焦点和正文对比度。

## Risks / Trade-offs

- 根会话承载注册表 → 仅作为稳定存储锚点，不与 root 归档绑定；测试 root 已归档、重启及 fork 不复制注册表。
- 新目录协议与浏览器镜像漂移 → 在契约测试中验证字段与服务 id，真实 WS 验证空工作区添加与通知。
- 高频目录广播与用户切换竞争 → 串行化导航操作、generation 隔离、测试另一客户端归档及断线中切换。
- 文件树可变、超大目录和权限失败 → 非递归分页、显式错误、添加时复核；并发文件系统变化下允许刷新重新分页。
- CSS 全局规则或 portal 泄漏 → 局部 tokens 与主题容器，浏览器同时检查导航及原聊天区域截图。

## Migration Plan

1. 在现有存储添加应用文档并幂等登记已保存的工作区，绝不清空已有历史；无绝对工作区的更旧存储仍按当前规则拒绝。
2. 先接通 gateway 工作区服务与测试，再更新 Web 服务发现、契约、状态机和界面。
3. 用临时存储和模拟 provider 验证多工作区、跨进程复用与真实浏览器交互，执行现有回归检查。
4. 回退代码不移除工作区文档，新增元数据保留；原会话 cwd 和历史格式不改变。仅空工作区在旧版 Web 中不可见，升级后再次出现。

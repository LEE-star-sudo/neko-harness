# Spec Delta

## ADDED Requirements

### Requirement: Web 升级感知与操作提示

Web SHALL 用简洁中文提示可安装更新、旧 gateway、旧静态服务和旧页面，并在设置中提供「关于与更新」入口。可安装更新 SHALL 提供复制 `neko update` 的操作；仅页面旧时 SHALL 提供手动刷新。Web MUST NOT 执行安装或重启服务，不自动刷新，不将提示发送给模型或反复弹窗。

#### Scenario: 可安装更新
- **WHEN** 后台确认较新稳定版本尚未安装
- **THEN** 显示“发现新版本，运行 neko update”及复制命令入口；远程浏览器明确在运行 neko 的电脑上执行

#### Scenario: 旧网关或旧静态服务
- **WHEN** 安装已更新，但 gateway 或提供页面的静态服务仍旧
- **THEN** 显示“已升级，请重新启动本地 neko”，详情指引关闭同一网关的 TUI/Web 或独立 serve 后再启动，不将刷新页面作为充分解决操作

#### Scenario: 仅页面旧
- **WHEN** gateway 和静态服务已更新，当前页面仍旧且协议兼容
- **THEN** 显示“页面已更新，刷新即可”及刷新入口，持续运行的页面通过检查获知变化，不依赖用户先刷新才发现更新

#### Scenario: 无法检查与关于页面
- **WHEN** 用户打开关于与更新页面，更新来源不可达或安装信息未知
- **THEN** 显示真实的组件版本与未知状态；主动检查失败时给出重试入口，聊天中的后台失败不持续打扰

### Requirement: 升级刷新与重新发现

用户触发升级刷新时，Web SHALL 保留当前会话的文字草稿及工作区/会话选择；有未发送附件、附件处理或提交正在进行时 SHALL 阻止该刷新并给出处理说明。连接重建 SHALL 重新发现并校验 gateway 地址、身份及版本，清除旧连接状态，不重复提交输入。非兼容协议错误 MUST NOT 无限自动重试。

#### Scenario: 文字草稿恢复
- **WHEN** 用户有未发送文字并点击升级提示的刷新入口
- **THEN** 页面重新加载后恢复同一工作区和会话的原文字，不自动发送；无法可靠保存时保留页面并显示提示

#### Scenario: 待发送附件
- **WHEN** 用户有未发送图片或附件处理/消息提交尚未完成，并点击刷新
- **THEN** 保持页面、草稿和附件，简短提示先完成提交或处理附件，不默默丢失文件

#### Scenario: gateway 重启换地址
- **WHEN** gateway 重启后地址变化，页面重新连接
- **THEN** 重新读取发现信息并验证当前身份，恢复原会话，使用新连接的版本状态，不持续连接旧地址

#### Scenario: 多种差异与响应式布局
- **WHEN** 页面在 375px/1440px 下同时发现网关、静态服务或页面版本差异
- **THEN** 优先展示需要先执行的操作，详细版本可在关于页面查看，按钮可键盘操作且页面无横向溢出；修复后移除过时提示

# Proposal

## Why

首次发布需要让用户知道何时可以升级，以及升级后哪些运行中的组件尚未生效。目前只有 `neko --version`，TUI/Web 会复用已有 gateway，无法区分安装已更新、网关仍旧或浏览器页面仍旧。

## What Changes

- 增加 `neko update`，检查 npm `latest` 并升级当前受支持的 Bun 全局安装，验证安装结果，明确输出成功、已最新或失败。
- 统一发布版本信息，分别识别安装包、运行中的 gateway、TUI/Web 静态服务和浏览器页面，独立判断协议兼容性。
- 后台检查新版本，使用缓存和超时，不阻塞启动和聊天；开发模式不自动检查或自升级。
- TUI/Web 只显示简洁提示和下一步：运行升级命令、重新启动界面/网关，或刷新页面。用户自行执行升级，不由界面触发安装或停止进程。
- Web 区分静态服务未重启与页面未刷新；提供安全的用户触发刷新入口，保留文字草稿，附件未处理时避免丢失。
- 文档补充推荐升级流程：完成任务、退出使用同一网关的界面及独立服务、执行 `neko update`、重新启动。

## Capabilities

### New Capabilities

- `application-updates`: 发布/安装版本识别、稳定渠道检查、用户触发的 CLI 自升级和升级状态判定。

### Modified Capabilities

- `session-gateway`: 提供服务器级版本与更新状态，连接时区分版本差异和协议不兼容，保持复用与拥有者关闭语义。
- `terminal-ui`: 英语升级提示、版本查看入口和可操作的重启说明。
- `web-ui`: 中文升级提示、关于与更新入口、页面/服务版本区分及保留草稿的手动刷新。

## Impact

- CLI 路由、core 的共享版本/状态逻辑、gateway 契约与连接接线、TUI 通知/命令、Web HTTP 信息/重连/设置页/草稿。
- 发布构建同时注入服务与浏览器版本，安装冒烟检查其一致性；不升级 Pi 依赖，不增加外部更新服务。
- 新增只读版本服务；没有安装或重启的远程 API。不修改会话数据库、提示词或模型请求。
- 支持现有文档中的 macOS/Linux Bun 全局安装。其他安装方式仅提供说明，不隐式创建第二份全局安装。Windows 不在本次支持平台扩展范围内。
- 不处理未正式发布的遗留用户迁移，不增加自动安装、自动重启、预发布渠道、降级或更新日志抓取。
